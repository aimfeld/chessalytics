<objective>
Make the abort signal actually reach Stockfish. `WorkerPool.grade` has implemented an
optional third `signal` parameter since Phase 154 — dequeuing an unstarted request and
posting `stop` to an in-flight one — and nothing has ever called it with a signal.
`dispatchExpansion` has `signal` sitting in its enclosing `mctsSearch` closure and drops it.

Purpose: this one wiring change closes ABORT-02 for free. All four `useBotGame` abort sites
already call `abortControllerRef.current?.abort()`, and that controller's signal already
flows through `createDeadlineSearch`'s outer-to-inner forwarding into `mctsSearch`. ABORT-02
is therefore a verification requirement — write the tests proving all four sites stop
in-flight work — not a four-site edit.

Output: an optional `signal?: AbortSignal` on `EngineProviders.grade`, `signal` threaded
through `dispatchExpansion` and through `fallbackExpectimax`'s symmetric call, the now-stale
Pitfall-1 comment in `useFlawChessEngine.ts` corrected, and tests covering the signal
forwarding plus all four bot-game abort sites.

Why `depends_on: [194-01]` despite zero file overlap: this plan edits `mctsSearch.ts`, which
`scripts/engine-mainthread-cost.mjs` exercises. Plan 01's first task captures the pre-phase
main-thread baseline against unmodified code, so no source edit in this phase may land before
that artifact is committed. The dependency is an ordering constraint on JANK-04's evidence,
not a code dependency.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
