<objective>
Make search snapshots lazy: a consumer reading only `rootMove`/`practicalScore`/
`childScoreSpread` pays nothing for `modalPath`/`modalStats`, while `onSnapshot` keeps firing
after every completed backup exactly as before.

Purpose: `buildRankedLines` calls `buildModalPath` eagerly for every root candidate (up to
`ROOT_CANDIDATE_HARD_CAP` = 15) on every snapshot. Bot play reads neither field, so that work
is 100% waste on the persona path; the analysis board renders roughly two of fifteen. But the
fix has a landmine that would make it a no-op: `botStyle.ts`'s `applyStyleScoreShaping` does
`{ ...line, practicalScore: ... }`, and object spread reads every own enumerable property
including accessors, baking the current value into a plain data property. That function runs
for every persona bot game — exactly the case this requirement targets. Shipping the getters
without fixing the spread ships a measurement of nothing.

Output: accessor-backed `modalPath`/`modalStats` sharing one memoized closure per line, a
descriptor-copying `applyStyleScoreShaping`, doc comments on the two type members warning
against spreading, and tests that prove non-invocation rather than value correctness.
</objective>
