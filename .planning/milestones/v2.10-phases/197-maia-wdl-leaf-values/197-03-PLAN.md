<objective>
Evaluate move quality under Maia WDL leaves on its own terms, before the change is accepted — and
lock the measured handoff depth into the shipped constant.

LEAF-04 is the requirement that stops this phase from being a speed optimization. The roadmap states
it plainly: a speed win alone does not satisfy this phase. So the instrument matters as much as the
result, and Phase 195's accept rule is the WRONG instrument here by construction — it measured mean
absolute practical-score agreement against a flat-depth-14 reference plus identical full ranked
order, and this change deliberately CHANGES leaf values, so high divergence is the expected outcome
rather than a disqualifying one.

The instrument that replaces it, declared before the run:
(a) a committed Maia-blindness fixture as a HARD BLOCKING gate — a regression there is a blocking
    finding, not a note;
(b) a head-to-head arm reporting which engine's chosen move the OTHER engine's objective grade
    prefers, which is a quality claim rather than a similarity claim;
(c) the D-02 scale offset and D-04 per-rung spread from Plan 02 as descriptive context, never gates.

The blindness fixture is not a generic position set. The failure mode is already documented and
verified: Maia has no history planes, so a post-sacrifice follow-up receives an unconditional prior
(game 687537 ply 46, confirmed NOT a sign bug), and today the Stockfish leaf is the only thing
pricing that follow-up. At a WDL leaf the value and the priors come from the same network, so they
agree by construction and the search loses its only external check. A general position set is
unlikely to be adversarial toward a failure mode we already know about — the fixture must be built
from that class deliberately.

Purpose: LEAF-04 (move quality evaluated before acceptance) and the code half of LEAF-02 (lock the
measured depth).
Output: a pre-declared accept rule, a committed fixture, a quality harness, results appended to
`reports/leaf-wdl/report.md`, and a blocking developer acceptance gate.
</objective>

**2. Declare the instrument, before running anything.** Write `reports/leaf-wdl/accept-rule.md`
following `reports/grading-ladder/accept-rule.md`'s structure (numbered sections, an explicit

- Why Phase 195's rule is not reused. Name it: that rule required mean absolute practical-score
  delta at or below the measured noise floor AND identical full ranked order against a
  flat-depth-14 reference. It is a SIMILARITY instrument, and this change intends to move leaf
  values, so it would fail a correct change and pass a change that did nothing.
- **Gate A (blocking): the Maia-blindness fixture.** The predicate: on every fixture position, the
  WDL-leaf engine's chosen root move must not be objectively worse than the Stockfish-leaf engine's
  chosen root move by more than a stated margin, where "objectively worse" is measured by an
  independent Stockfish grade of BOTH chosen moves at a fixed depth stated here. Declare the margin
  and the depth now. Declare explicitly that a regression on this set is a BLOCKING finding that
  stops the phase, not a note in a Limits section.
- **Gate B (reported, not blocking): the head-to-head arm.** The predicate: over a shared position
  set at the same node budget, run both engines, then for each position grade BOTH chosen moves with
  an independent Stockfish search and report which engine's move the other's objective grade
  prefers, as a win/loss/tie count. Declare the position set, the node budget, the grading depth, and
  the tie band now. State that this is a quality claim, and that a head-to-head loss is a strong
  signal to reject even though it is not mechanically blocking.
- **Context (never a gate): D-02 and D-04.** The scale offset and per-rung spread from Plan 02 are
  reported alongside for interpretation and are explicitly not acceptance criteria.
- **Continuity, labelled as description.** Agreement-versus-Stockfish-leaves may be reported for
  continuity with Phase 195's numbers, and must be labelled description, not acceptance.
- **The fallback clause.** State what happens if Gate A passes but Gate B is a clear loss, and what
  happens if the fixture turns out too small to discriminate.

**3. Build the fixture.** Create `fixtures/engine/maia-blindness.tsv` — a small committed set (aim
for 10 to 15 positions; enough to discriminate, small enough to run in minutes) of positions where
Maia's policy is known or expected to be blind. Columns: an id, the FEN, the objectively correct
move in UCI, a one-line note on why Maia is expected to miss it, and the source. Populate it from
the documented class deliberately:
- The verified anchor: game 687537 ply 46 and the position one ply after the sacrifice, where the
  follow-up receives an unconditional prior because Maia has no history planes. Pull the FEN from
  the database rather than transcribing it.
- Forced-sacrifice positions more broadly: positions where the objectively best move is a material
  sacrifice whose justification only appears in the follow-up.
- For each candidate, verify with a real Stockfish search that the recorded correct move IS
  objectively best, and record the eval gap to the runner-up in a column, so a position with a
  near-tie best move cannot silently weaken the gate.

is for and that a regression on it blocks the phase.

  <action>
Write `scripts/engine-wdl-leaf-quality.mjs`, a sibling of `scripts/engine-grading-depth-ab.mjs` that
runs the two arms the accept rule declares. Reuse `scripts/lib/node-engine-providers.mjs` and
`scripts/lib/calibration-providers.mjs` for all engine bring-up — do not duplicate spawn or session
code (the CAL-02 no-duplicate-bring-up discipline). Support at minimum `--fixture <path>`,
`--fens <path>`, `--nodes`, `--plies`, `--elo`, `--procs`, `--grade-depth`, and `--out-dir`,
following the existing script's flag-parsing and usage-block conventions.

For each position the script runs the search TWICE at the same node budget with everything else held
fixed: once with the WDL-leaf path active and once with it disabled so every leaf takes a Stockfish
grade. It then grades BOTH chosen root moves with one independent Stockfish search at the
accept-rule's declared depth, and emits one TSV row per position carrying: the position id, the FEN,
the WDL arm's chosen move and its independent objective eval, the Stockfish arm's chosen move and
its independent objective eval, the signed eval delta, and both arms' wall clock and grade-call
counts.

Gate A behaviour: when `--fixture` is supplied, the script additionally compares each arm's chosen
move against the fixture's recorded correct move, computes the regression predicate the accept rule
declared, prints a per-position pass or fail line, and EXITS NON-ZERO if any position regresses.
This is what makes the gate a gate rather than a report — model it on the project's existing
committed-fixture precision gate, which exits non-zero until its floors are met.

Run it: Gate A over `fixtures/engine/maia-blindness.tsv`, and Gate B over the shared position set
the accept rule named, both at the accept-rule's declared budget and grading depth. Commit every TSV
under `reports/data/`.

Then append a "LEAF-04 — move quality" section to `reports/leaf-wdl/report.md` containing:
- The Gate A result per fixture position, with the verdict stated as pass or BLOCKING FAILURE.
- The Gate B head-to-head win/loss/tie counts, expressed as which engine's chosen move the other's
  objective grade preferred — not as an agreement percentage.
- The D-02 offset and D-04 spread from Plan 02, cross-referenced as context, explicitly not gates.
- If reported at all, agreement-versus-Stockfish-leaves under a heading that labels it description
  for continuity with Phase 195, not acceptance.
- A Limits section in the same shape as `reports/grading-ladder/report.md`'s, including the known
  caveat that Stockfish evals are not bit-reproducible across machines, so a sub-noise delta is not
  a signal.

Every figure must trace to a committed TSV row. If Gate A fails, write the section reporting the
BLOCKING FAILURE honestly and stop — do not soften it, do not retune the fixture to make it pass,
and do not proceed to Task 3 as if it were a normal acceptance.
