<objective>
Build the "before" side of D-08's timing comparison while the sweep runs. The harness has always
logged per-ply wall clock to stdout, so the pre-195 measurement already exists — but only as
gitignored local files on one machine. Parse it into a small committed artifact so the claim is
auditable rather than asserted.

Purpose: this is the first game-level evidence for the grading ladder's payoff. Every measurement so
far is fixture-level — a 12-position blindness fixture and a 21-position Stage A set. The fixture
claim to test against is 1.35x wall clock and a 61.4% cut in grade CPU at the bot budget.

This plan is deliberately non-blocking on the sweep: it reads only pre-existing local logs and writes
only new files, so it proceeds in parallel with plan 06's multi-hour wait.

Output: `scripts/parse_calibration_timing_baseline.py` and
`reports/data/bot-parity-199-timing-baseline.json`.
</objective>

  <name>Task 1: The pre-195 run-log timing parser</name>
  <files>scripts/parse_calibration_timing_baseline.py</files>
  <behavior>
    - Given a fixture of a few well-formed per-ply lines, the parser extracts ply number, mover and
      seconds for each, and computes the total elapsed and the bot-only mean.
    - A line whose mover is the anchor contributes to the total but not to the bot-only mean.
    - A malformed line, or a line from an unrelated log stream, is skipped without raising, and the
      count of skipped lines is reported.
    - A fixture containing the retired maia900 anchor token raises rather than returning a result.
    - A fixture whose ply-run structure does not line up with the supplied per-game ply counts raises
      rather than mis-attributing plies to the wrong cell.
  </behavior>

      fail-loud-on-malformed fixture case, and the `main(argv)` entry-point shape.

    - `reports/data/sweep-human/calibration-harness-2026-07-19T21-13-45-244Z.tsv` — a committed raw

  <action>
    Create `scripts/parse_calibration_timing_baseline.py`, stdlib only (`argparse`, `json`, `re`,
    `csv`, `pathlib`, `subprocess`, `sys`, `statistics` if useful — no numpy, no scipy), with the
    module-header conventions from `calibration_anchor_fit.py` and the `--self-test` convention from
    `calibration_persona_fit.py`.

    Define the per-ply line pattern as a single named module-level constant, `PLY_TIMING_RE`, matching
    the harness's own stdout shape: the harness log prefix, the word ply, the ply number, a
    parenthesised mover that is either the bot or the anchor, the move in UCI, and the elapsed
    seconds as a decimal followed by the unit. Capture the ply number, the mover and the seconds.

    Implement `parse_run_log(log_path, ledger_path)` returning per-cell timing aggregates. The
    attribution problem is the substantive part: the log lines carry no cell marker, so cells must
    come from the sibling committed raw ledger in the same out-dir, which does carry `bot_elo`,
    `bot_blend`, `game_index` and `plies` per completed game. Walk the log's ply lines in order,
    segmenting them into games at each ply-number reset, and consume the ledger's rows in the same
    order, using each row's recorded ply count to confirm the segment length. When a segment's length
    does not match the ledger row's ply count, raise with both numbers in the message rather than
    silently sliding the join by one game — a slipped join would attribute an entire cell's timings
    to its neighbour and is exactly the failure this baseline cannot survive.

    Reject a retired-scale log explicitly: if the log or its sibling ledger contains the retired
    `maia900` anchor token, or a blend value outside the current preset blends, raise with a message
    naming the 2026-07-12 clamped-run incident. This is what keeps the two unusable root-level logs
    out of the baseline even if someone points the parser at them.

    Per cell, emit total wall clock, mean per-game elapsed, mean per-bot-move milliseconds, the game
    count and the ply count, plus the count of unparseable lines skipped.

    Add `--self-test` as an early-return argparse branch covering exactly the five cases in this
    task's `<behavior>` block, using a small hardcoded fixture of synthetic log lines carrying an
    inline comment that they are illustrative and not real captured output. Print a single success
    line naming the module.

    Keep functions inside CLAUDE.md's limits — nesting depth at most 3. The natural split is one
    function for line parsing, one for game segmentation, one for the ledger join, and a thin
    orchestrator; do not nest the segmentation loop inside the join loop inside the file walk.
  </action>
