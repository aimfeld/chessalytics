<objective>
Build the complete backend push-delivery chain end to end and prove it in one
pass: a browser subscription lands in a new `push_subscriptions` table, a real
VAPID-signed `aes128gcm` payload is produced for it, an `httpx.AsyncClient`
POSTs it to the browser-supplied push endpoint, and dead endpoints prune
themselves. A dev-only trigger endpoint fires that whole chain on demand for
the calling user, which is the only way to exercise it before Phase 202 builds
the subscribe UI.

Purpose: this is the phase's tracer. Every later plan (service worker, settings
API, scheduler) is expansion on top of a chain that is already proven to work.
If the crypto/transport choice is wrong, it is wrong after one commit, not ten.

`push_repository`, `app/schemas/push.py`, `push_send` service, `push` router
(subscribe / unsubscribe / vapid-public-key / dev-trigger), the notification
copy builder, `scripts/gen_vapid_keys.py`, VAPID config settings, an opt-in
`push` dependency group, and three new test files.

<assumption_delta_decision>
The `assumption-delta` detector fired (`pluralization`, `chosen`). The real
delta this phase carries: a user goes from having no push identity at all to
having N device subscriptions.

- **Primary noun: `user`.** A reminder is a per-user event; a subscription is a
  delivery detail of that one event.
- **Decision: `no-change` (the identity model already names the right noun).**
  The daily idempotency ledger (`train_settings.reminder_last_sent_on`, D-06)
  stays user-scoped rather than being promoted to per-subscription. Rationale:
  promoting it would make "one reminder per user per day" mean "one per device
  per day", which is a different and wrong product behaviour — D-05's fan-out
  is explicitly one message delivered to many devices, not many messages.
- Debt accepted: none. What would force a revisit: a second notification type
  (out of scope per SEED-132), which would need the ledger keyed by
  `(user_id, notification_type)`.
</assumption_delta_decision>

**Step 3 — repository (`app/repositories/push_repository.py`).** All functions

`p256dh: str`, `auth: str`);
`upsert_subscription(session, *, user_id, endpoint, p256dh, auth, user_agent) -> int`
using `pg_insert(PushSubscription).values(...).on_conflict_do_update(index_elements=["endpoint"], set_={...})`
returning the row id — so a re-subscribe from the same browser updates the keys
and the owning user in place instead of raising on the unique constraint;
`list_subscriptions(session, *, user_id) -> list[PushSubscriptionRow]`;
`delete_subscription_by_endpoint(session, *, user_id, endpoint) -> int`
(scoped to the owner — deleting another user's endpoint must match zero rows);
`delete_subscription_by_id(session, *, subscription_id) -> None` (the prune
path; a delete of an already-deleted id is a no-op, which is what makes pruning
idempotent). No business logic here, no `httpx`, no config reads.

**Step 4 — send service (`app/services/push_send.py`).** Start from
`201-RESEARCH.md` Code Example 3 and extend it:
module constants `_PRUNE_STATUS_CODES = frozenset({404, 410})`,
`_VAPID_EXPIRATION_SECONDS = 12 * 60 * 60`, `_PUSH_TIMEOUT_SECONDS = 10.0`.
`is_push_configured() -> bool` returns True only when both key settings are
non-empty.
`build_webpush() -> WebPush | None` returns None when unconfigured, else
constructs `WebPush(private_key=..., public_key=..., subscriber=settings.VAPID_SUBJECT, expiration=_VAPID_EXPIRATION_SECONDS)`
passing the PEM values `.encode()`d as bytes (the library accepts
`bytes | Path | BytesIO | StringIO`; bytes avoids needing key files in the
container).
`application_server_key() -> str | None` derives the base64url raw
application-server key the browser's `PushManager.subscribe` needs, from the
PEM in `VAPID_PUBLIC_KEY`: load it with
`cryptography.hazmat.primitives.serialization.load_pem_public_key`, emit
`public_bytes(Encoding.X962, PublicFormat.UncompressedPoint)`, then
`base64.urlsafe_b64encode(...).rstrip(b"=").decode()`. Derive it rather than
storing a fourth env var — a PEM and a hand-pasted base64url that drift apart
would silently 403 every send.
`push_http_client() -> httpx.AsyncClient` builds the client with
`timeout=_PUSH_TIMEOUT_SECONDS` and `follow_redirects=False` (ASVS V4/SSRF: the
endpoint is client-supplied, so an outbound redirect must never be chased to a
new host).
`send_to_subscription(client, *, endpoint, p256dh, auth, payload) -> bool`
returns True meaning "prune this row": build the `WebPushSubscription`, call
`.get(...)`, `await client.post(endpoint, content=message.encrypted, headers=dict(message.headers))`.
Branch explicitly: status in `_PRUNE_STATUS_CODES` -> return True, no Sentry
(a dead endpoint is not an error); any other status >= 400 -> `logger.warning`,
`sentry_sdk.set_tag("source", "push_send")`,
`sentry_sdk.set_context("push_send", {"status_code": resp.status_code})`,
`sentry_sdk.capture_exception(RuntimeError("Push send returned a non-success status"))`
with a FIXED message string and the code only in the context (CLAUDE.md: never
embed variables in Sentry messages), return False; `httpx.HTTPError` ->
log + capture + return False (D-04: no retry, no backoff, never delete on a
transient failure).
`PushFanoutResult` (frozen dataclass: `attempted: int`, `pruned: int`,
`failed: int`) and
`async def send_to_user(session, *, user_id, payload) -> PushFanoutResult`
opens ONE `push_http_client()` for the whole fan-out (connection pooling across
a user's devices), iterates `push_repository.list_subscriptions` sequentially
(never `asyncio.gather` — one `AsyncSession`), calls `send_to_subscription` per
row, and calls `delete_subscription_by_id` for each True, committing once at
the end. Returns a zero-valued `PushFanoutResult` immediately when
`is_push_configured()` is False.
This module must contain no `requests`-module import and no `asyncio.to_thread`
call — the whole point of D-01.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/push/subscribe` | Untrusted client supplies an arbitrary `endpoint` URL plus two key blobs that the backend will later POST to |
| backend -> external push service | Outbound HTTPS to a host chosen by the client's subscription, not by us |
| operator `.env` -> process env | The VAPID private key crosses from disk into the running process and must go no further |
| any client -> `POST /api/push/dev/trigger-reminder` | A route that must be inert everywhere except a developer's machine |
