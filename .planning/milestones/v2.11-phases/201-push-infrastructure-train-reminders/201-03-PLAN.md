<objective>
Land the reminder configuration on `train_settings` and expose it through the
Train settings API that already exists, so the whole reminder surface is
configurable with `curl` before Phase 202 writes a single line of UI.

Purpose: plan 201-04's scheduler reads `reminder_enabled`, `reminder_hour` and
`reminder_last_sent_on` off the row it already loads. This plan is what puts
them there, and D-18's decision to expose them now is what keeps Phase 202
purely frontend.

Output: a second Alembic revision adding three columns and one CHECK
constraint, the matching model fields, `TrainSettingsRow` and the three
repository functions carrying them, the two Train settings schemas gaining the
two client-facing fields, and tests at both the repository and router level.
</objective>
