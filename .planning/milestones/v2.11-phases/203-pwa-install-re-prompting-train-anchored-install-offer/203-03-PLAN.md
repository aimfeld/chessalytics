<objective>
Turn `TrainReminderButton`'s single implicit state into five explicit named states, and make
the confirmed state the upsell surface: an install offer on Android tabbed, a desktop→phone
QR handoff on desktop, and deliberately nothing on standalone. Give the QR its permanent
second home in `TrainScheduleSettings`.

Purpose: this is where the phase's value lands. Phase 202 built the reminder opt-in; this
plan turns the moment a user grants it — peak intent, zero cost to ignore — into the surface
that routes them onto a phone. The `ios-tabbed` state is NAMED by the resolver here but its
render is filled in Plan 04, per D-17's requirement that a bad iOS storage answer costs one
plan rather than the phase; until then it resolves to the same structural absence as today,
which is the fail-safe behavior.

Output: a pure resolver with exhaustive unit coverage, a shared QR component with two mount
points, the Android install offer, and the `qrcode.react` dependency.
</objective>
