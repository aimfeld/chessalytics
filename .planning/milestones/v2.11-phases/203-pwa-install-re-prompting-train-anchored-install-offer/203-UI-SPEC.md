# Phase 203 — UI Design Contract

> Visual and interaction contract for PWA install re-prompting, the five-state `TrainReminderButton`,
> the iOS Add-to-Home-Screen slice, and the desktop→phone QR handoff. Generated by gsd-ui-researcher
> from `203-CONTEXT.md` (LOCKED decisions D-01..D-17) and `203-RESEARCH.md` (codebase inventory).
> Every decision below either restates a LOCKED CONTEXT.md decision (marked `[LOCKED]`) or resolves an
> open discretion point CONTEXT.md deliberately left to this pass (marked `[UI-SPEC]`).

**This phase touches NO new visual language.** No new component library additions, no new brand
colors, no new type scale. It restyles/extends four existing surfaces (`InstallPromptBanner`,
`TrainReminderButton`, `TrainScoreScreen`, `TrainScheduleSettings`) using the app's existing `Button`
variants, `Card`/`CardHeader`/`CardBody` primitives, `theme.ts` constants, and `text-sm` floor. The one
net-new visual element is the QR code block (two call sites), whose only new visual rule is a
forced light-mode chip so the code stays scannable inside FlawChess's dark theme.

## Typography

Declared for **new copy authored by this phase only** — pre-existing untouched components
(`DrawerTitle` at `text-base font-medium`, `TrainScoreScreen`'s `h1` at `text-xl font-semibold`) are
inherited unmodified and out of this phase's typography contract.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / copy | 14px (`text-sm`) | 400 (regular) | 1.5 — drawer body, iOS instructions, QR captions, re-surface banner body |
| Label / semibold emphasis | 14px (`text-sm`) | 600 (semibold, `font-semibold`) | 1.2 — re-surface banner headline, QR block section caption in Settings |

Two weights only (regular 400, semibold 600), per CLAUDE.md's `text-sm` floor — no `text-xs` anywhere
in this phase's new copy. Buttons inherit their own `font-medium` (500) from the untouched shared
`Button` primitive (`buttonVariants` base class) — that is pre-existing app-wide styling, not a new
weight this phase introduces, so it does not count against the 2-weight budget above.

**Honest functional check (non-blocking checker note):** a screen combining this phase's new copy with
existing buttons DOES render 3 distinct weights on screen (400 body / 500 buttons / 600 labels) — the
2-weight budget above governs only content this phase *authors*, not the full rendered page. This is not
a new condition this phase introduces: `font-medium` (500) is baked into the shared `Button` component
and has rendered on every button in the shipped app (the pre-existing "Remind me"/"Install"/"Not now"
buttons included) since before this phase touched anything. No screen in this phase adds a 4th weight,
and no new component invents its own button styling outside `buttonVariants` — so the app-wide weight
count is unchanged by this phase, even though the on-screen total is technically 3, not 2.

## Color

This app themes via Tailwind semantic tokens (`bg-background`, `bg-card`, `text-muted-foreground`,
`bg-brand-brown`) and `lib/theme.ts` oklch constants, not literal component-level hex — this phase
follows that convention exactly; no new hex/oklch constant is added to `theme.ts`.

| Role | Token / Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `bg-card` (existing) | Score screen, Settings card body, Drawer surface |
| Secondary (30%) | `text-muted-foreground` | All new body copy (drawer text, QR captions, confirmed-span text) — matches the existing confirmed-span and `ReminderControls` label treatment |
| Accent (10%) | `bg-brand-brown` (via `Button variant="default"`) | **Reserved for exactly:** the drawer's "Install" CTA (unchanged), the re-surface banner's "Turn on reminders" primary CTA. Every other new control in this phase is `variant="brand-outline"` (secondary) or `variant="ghost"` (tertiary/dismiss) — never a second `default`-variant button competing for attention on the same screen. |
| Destructive | `variant="destructive"` (existing) | Not used — this phase has no destructive action |

**QR contrast contract (new, load-bearing):** the QR module MUST render as solid black modules on a
solid white background, inside a small white rounded chip (`bg-white rounded-md p-2`), regardless of
FlawChess's charcoal-textured card surface or any future light/dark theme. **Do not** tint the QR with
`theme.ts` colors, apply the app's dark-card background behind it, or invert it for dark mode — a
theme-tinted or inverted QR is a scan-reliability risk (`HANDOFF-01`/`203-RESEARCH.md`'s explicit
"QR must render fully offline" constraint extends to "must render at guaranteed-scannable contrast").
The white chip is the ONLY new non-token color surface this phase introduces, and it is fixed
(`#FFFFFF` background / `#000000` modules) precisely because it must NOT follow the app theme.

Accent reserved for: **drawer "Install" button, re-surface banner "Turn on reminders" button — nothing
else.** The Android-tabbed confirmed-state install offer, the iOS-tabbed instructions button, and both
QR blocks are deliberately NOT accent-colored (see Copywriting Contract + UI Considerations) — they are
zero-cost-to-ignore secondary/tertiary surfaces per D-08/D-13, and accenting them would compete with the
screen's real primary action (`Done`, or the drawer's own `Install`).

subscribe) in the same slot — a test asserting "the iOS-tabbed user sees the iOS affordance" must not
have to also match on label text as a platform proxy. Reusing one id across states with different
behavior is exactly the ambiguity CLAUDE.md's per-element `data-testid` rule exists to prevent.

**Icon-only sweep (confirms no new `aria-label` is required):** every new interactive element in this
phase carries visible text alongside its icon (`Install FlawChess`, `Get reminders`, `Turn on reminders`,
`Not now`) — none is icon-only, so none needs a new `aria-label` under CLAUDE.md's rule 3. All new
decorative icons (`Smartphone`, and the `Bell` leading the re-surface headline) carry `aria-hidden="true"`,
matching the existing convention already used for `Check`/`Bell` elsewhere in `TrainReminderButton.tsx`
and `TrainScoreScreen.tsx` — not a new pattern this phase invents.

**Existing testids reused unchanged (no action needed, listed for completeness):**
- `btn-train-remind-me` — the unsubscribed-state button, shared verbatim across THREE of the five states
  (`desktop-unsubscribed`, `android-tabbed-unsubscribed`, `standalone-unsubscribed`) because those three
  states render the literal same label/behavior — this is the correct id-sharing case, unlike the iOS one
  above, precisely because the component and its behavior are identical, not merely similarly styled.
- `train-reminder-confirmed` — the `subscribed`-state span, unchanged.
- `btn-install`, `btn-install-dismiss`, `install-prompt-android` — Android drawer (§1), unchanged.
- `banner-ios-install`, `btn-ios-install-dismiss` — generic iOS banner (§1), unchanged.
- `train-schedule-settings` — the Settings card root that now also contains the §4 Settings QR block.

## Interaction Contract (surface-by-surface, prescriptive)

### 1. Install drawer / banner (INSTALL-01, INSTALL-02 superseded by D-03)

- **Mounts:** unchanged — `App.tsx:613` (analysis-takeover layout) and `App.tsx:638` (default layout).
  Both keep firing on first mobile visit (D-03 — the demonstrated-value gate is dropped, not built).
- **Suppression:** renders nothing on any `/train*` route (`pathname.startsWith('/train')`, D-07) —
  **except** when the URL carries `?src=handoff` (D-11), in which case suppression is bypassed and the
  D-04 cooldown is also bypassed for that load.
- **Dismiss affordance:** unchanged controls (`btn-install-dismiss` "Not now" / `btn-ios-install-dismiss`
  X icon). Visually IDENTICAL every time — see UI Considerations row "no visual difference between
  cooldown and capped-out."
- **Cooldown/cap:** `INSTALL_COOLDOWN_DAYS = 14`, `INSTALL_MAX_ATTEMPTS = 3` (D-04, named constants,
  never literals). Purely a visibility gate — zero new UI.
- **Event retention:** the captured `BeforeInstallPromptEvent` is never read by the drawer's own
  rendering — it is a hidden precondition (`!!promptEvent`). Its retention (INSTALL-04) has no visual
  spec of its own; it is what makes the Android-tabbed confirmed-state install offer (§3 below)
  possible without a dead button.

### 2. `TrainReminderButton` five-state resolution (OFFER-01)

Resolution priority (first match wins) — a UI contract, not just logic, because it determines which
button/copy/icon renders in the same DOM slot:

1. `subscribed` (this device has a push subscription) → confirmed span (`Check` + "Reminders on…",
   unchanged) + platform-conditional upsell per §3/§4/§5 below.
2. `isIOS && !isStandalone` → `ios-tabbed`: "Get reminders" button (§6).
3. `isStandalone && !subscribed` → `standalone-unsubscribed`: plain "Remind me" button, confirmed
   state carries **no** upsell (OFFER-04).
4. `isMobile && !isIOS` (Android tabbed) `&& !subscribed` → `android-tabbed-unsubscribed`: plain
   "Remind me" button, confirmed state carries the install-offer upsell (§3).
5. else (desktop tabbed) `&& !subscribed` → `desktop-unsubscribed`: plain "Remind me" button, confirmed
   state carries the QR upsell (§4).

All five states share ONE visual shape for the unsubscribed button (`Bell` icon, `variant="brand-outline"`,
same slot/row) — only the label and the post-tap behavior differ (§6 for iOS). This keeps the row's
layout stable across every platform, per CLAUDE.md's "apply changes to mobile too" spirit even though the
five states are themselves platform-branched.

### 3. Android-tabbed confirmed-state install offer (OFFER-02)

- Renders directly below the existing confirmed span (`Check` + "Reminders on…"), same `gap-2` vertical
  stack, still inside the existing `train-score-button-row` container.
- Shape: `Smartphone` icon (16px, `size-4`, matching the existing `Check`/`Bell` icon sizing convention)
  + "Install FlawChess" text, `text-sm`, styled as a low-emphasis `variant="ghost"` `size="sm"` button —
  never `variant="default"` or `"brand-outline"` (reserving those for the screen's real primary actions
  per the Color section's accent-reservation rule).
- Gated on `!!promptEvent` (see UI Considerations "empty" row) — absent, not disabled, when there is
  nothing to trigger.
- **Test ID:** `data-testid="btn-install-android-offer"` (see Test IDs & Accessibility table).

### 4. Desktop confirmed-state QR offer (HANDOFF-01..04, D-09/D-10)

- **Score screen:** renders in its own row beneath the confirmed span + button row (not sharing a flex
  row with `Done`), desktop-only (this state only resolves for `desktop-unsubscribed`/`subscribed`
  desktop users per §2's priority order — no explicit viewport check needed beyond the state resolver
  itself).
- **Settings:** a new block inside `TrainScheduleSettings`'s existing card body, below `ReminderControls`
  (composition point `TrainScheduleSettings.tsx:452-461`), following the same `<div className="w-full">`
  + `text-sm text-muted-foreground` label pattern already used for "Train on" / "Puzzles per session".
- **Component:** `qrcode.react`'s SVG export (exact export name confirmed at implementation time per
  `203-RESEARCH.md` Open Question 1 — not hard-coded here). Size **128×128px**, error-correction level
  **`M`** (the library default; the payload is a short plain URL with one query param, well within `M`'s
  capacity margin — no need for the denser `Q`/`H` levels this payload doesn't require).
- **Chip:** `bg-white rounded-md p-2` wrapper around the QR SVG, fixed regardless of theme (see Color
  section's QR contrast contract). Caption below the chip, `text-sm text-muted-foreground` (Copywriting
  Contract row).
- **No dismiss control anywhere** (D-13, deliberate deviation from HANDOFF-03's literal wording) — do
  not add an `X` button or a persisted dismiss flag to either QR mount point.
- **Payload:** the current page's canonical URL + `?src=handoff`, no credential, no token (HANDOFF-01).
- **Test IDs:** `data-testid="qr-handoff-score"` (score-screen mount) / `data-testid="qr-handoff-settings"`
  (Settings mount) — one shared component, mount-site-specific id passed as a prop (see Test IDs &
  Accessibility table for why these must not collide on one hardcoded id).

### 5. Standalone-unsubscribed confirmed state (OFFER-04)

- No visual change from today's single confirmed span. This row exists in the table purely to make
  explicit that the resolver must NOT fall through to §3 or §4 for this state.

### 6. iOS-tabbed slot (OFFER-03, D-14/D-15)

- Same slot, same row, same `Bell`-icon/`brand-outline` shape as the default "Remind me" button, label
  "Get reminders" (Copywriting Contract).
- On tap: (a) `PUT /train/settings` writes `reminder_intent_at` synchronously — **before** any UI
  transition (D-15, Pitfall 5 in `203-RESEARCH.md`: must not ride the debounced-draft path); (b) render
  the honest two-step instructions body (Copywriting Contract, `[iOS-only]` row) in place of the button,
  reusing `InstallPromptBanner`'s existing `Share` icon + "tap **Share** then **Add to Home Screen**"
  wording as a lead-in, followed by the new "then open it and turn on reminders" continuation — one
  coherent three-step reading, not two disconnected copy blocks.
- No dismiss/close control on this instructions body — it is inline, replaces the button in place
  (matches the `ERROR_COPY` in-place-replace pattern already used elsewhere in this component), and
  disappears naturally on the next navigation.
- **Test IDs:** button `data-testid="btn-train-ios-reminders"` (NOT `btn-train-remind-me` — see Test IDs
  & Accessibility table for the explicit rationale); instructions body
  `data-testid="train-ios-reminder-instructions"`.

### 7. Post-iOS-install re-surface prompt (OFFER-05, D-16)

- **Trigger:** standalone launch, `reminder_intent_at` is set server-side, this device has no push
  subscription. On trigger: `useNavigate()` to `/train` (not a passive `start_url` behavior — must be an
  active route push per `203-RESEARCH.md`'s `start_url: '/'` finding), THEN render the banner.
- **Placement:** a dedicated `Card` (accent-spine `accentColor` = the brand-brown token, matching the
  primary-CTA accent reservation) mounted above `TrainStartScreen`'s existing landing content — not a
  modal, not blocking navigation, not gated behind starting/completing a session (that is exactly the
  two-session cliff OFFER-05 exists to close).
- **Visual priority (resolves the checker's Visuals FLAG):** this Card is the FIRST thing on the landing
  view, ahead of the streak card and every other landing element — not a secondary strip below the page
  header. Surfacing it promptly, at the top of first paint on this exact standalone launch, is the entire
  point of OFFER-05 closing the two-session cliff; demoting it below the fold or below the streak card
  would recreate the same "user has to go hunting" failure this requirement exists to fix.
- **Content:** headline + body + primary CTA + dismiss, per Copywriting Contract. `Bell` icon leading the
  headline (16px, matches the app's existing reminder-iconography convention from `TrainReminderButton`).
- **Clears itself:** on successful subscribe (re-run the same `getDeviceSubscription()` mount-check that
  gates its own rendering) or on dismiss (a per-device `localStorage` boolean — new key, distinct from
  both the D-04 cooldown keys and `reminder_intent_at`; e.g. `train-resurface-dismissed`). **[UI-SPEC —
  Claude's Discretion per CONTEXT.md's "test strategy for navigator.standalone" open item; the exact
  storage key name is an implementation detail, the one-boolean-per-device shape is the contract.]**
- **Test IDs:** root `data-testid="resurface-banner"`; headline `data-testid="resurface-banner-headline"`;
  primary CTA `data-testid="btn-resurface-turn-on"`; dismiss `data-testid="btn-resurface-dismiss"`.
