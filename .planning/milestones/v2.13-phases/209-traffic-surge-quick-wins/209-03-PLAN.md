<objective>
Bound the readiness poll (SEED-146 item 1, the highest-impact fix in the phase): keep the
3 s cadence while an import is in flight, decay hard once only tier2 is outstanding, and
stop entirely after a 30-minute backoff budget — with the emitted interval sequence itself
as the tested artifact (D-05).

Purpose: `useReadiness` is mounted on essentially every page and today stops only when
tier2 is true, which for a days-long eval drain means never. At 300 concurrent tabs that is
~100 req/s of the heaviest read query on the site, standing load proportional to concurrent
users, before a single import or signup happens.
Output: a deterministic ladder + budget in one hook, and a fake-timer test that asserts the
emitted deltas and goes red when the backoff is reverted.
</objective>

## Locked planning decisions for the discretionary values (D-05)

CONTEXT.md defers the curve and the cap to the planner. They are fixed here so the test can
assert an exact sequence:

| Constant | Value | Reason |
|----------|-------|--------|
| `READINESS_POLL_INTERVAL_MS` | `3_000` (existing, unchanged) | The import phase is seconds-to-minutes; SC-1 requires this cadence while tier1 is false. |
| `READINESS_BACKOFF_LADDER_MS` | `[15_000, 60_000, 300_000]` | Three steps, clamping at 5 minutes. Integer literals, so the emitted sequence is exactly assertable and cannot drift through float math. |
| `READINESS_BACKOFF_BUDGET_MS` | `30 * 60_000` | "A tab open for 8 hours should not still be asking" (seed). 30 minutes of tier2-waiting yields ~8 requests instead of ~600. |

Budget semantics: the budget clock starts when tier1 first becomes true with tier2 false,
and resets whenever tier1 goes false again. It bounds the *quiet* phase only — the 3 s
cadence during an active import is bounded by the import itself and by
`IMPORT_TIMEOUT_SECONDS`, and D-05 explicitly asks for that cadence to be preserved.
