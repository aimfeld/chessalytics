# Plan 210-01: Frontend Replay Containment

## Requirements

| ID | Statement | Success Criterion |
|----|-----------|-------------------|
| CUSTOM-01 | Seeding `/analysis` with a SAN sequence illegal from its root renders a partial or empty board and leaves the page mounted — it never reaches the React ErrorBoundary | SC-1 |

## Background

`chess.js` 1.4.0's `move()` **throws** on illegal SAN rather than returning null
(`chess.js/dist/esm/chess.js:2527`). Four replay loops in the codebase guard with
`if (!move) break`, which is therefore dead code — the throw escapes instead.

Confirmed in prod as **Sentry FLAWCHESS-96** (`Error: Invalid move: Nd3`, 3 events, first
seen 2026-07-24, `transaction: /analysis`, Chrome Mobile/Android): `Analysis.tsx` seeding
effect → `loadMainLine` → `chess.js O0.move` → React ErrorBoundary. The whole `/analysis`
page unmounts. `Users Impacted: 0` is a Sentry artifact (no user context attached), not
evidence of low impact.

The correctly-guarded precedents to copy are `treeCommon.ts:222`, `analysisUrl.ts:58`,
`sanToSquares.ts:19` and `TrainLineStepper.tsx:139`, which all already try/catch.

## Tasks

### Task 1 — Reproduce the crash as a failing test

Add to `frontend/src/hooks/__tests__/useAnalysisBoard.test.ts`:

- `loadMainLine` with a custom-start game's SANs against the standard `STARTING_FEN`. Use a
  sequence whose first move is legal and whose second is not, so the partial-retention truth
  is exercised too. Assert the hook does not throw and the main line holds exactly the legal
  prefix.
- `insertPvLine` with a PV whose second SAN is illegal from the fork node. Assert no throw and
  that the nodes for the legal prefix exist.

Both must FAIL before Task 2 (that is the mutation proof — record the observed failure in the
summary).

### Task 2 — Contain the four replay sites

Replace the dead `if (!move) break` guard with try/catch + `break` at:

- `useAnalysisBoard.ts:399` (`loadMainLine`) — confirmed crash site
- `useAnalysisBoard.ts:474` (`insertPvLine`) — same idiom, worse blast radius: it throws
  inside a `setState` updater, and the PV SANs cross a worker boundary
  (`treeCommon.ts:218` documents exactly this hazard for the sibling UCI path)
- `useChessGame.ts:147` (`replayTo`)
- `useBotGame.ts:299` (`replayToPly`)

The latter two replay our own stored history so they are lower risk, but they are the same
latent crash and are cheap to fold in.

Each catch must carry a comment naming the bug (chess.js 1.4 `move()` throws; the old
`if (!move)` guard was dead) per CLAUDE.md's "comment bug fixes" rule. Do not add Sentry
capture here — an unreplayable line is an expected condition once slice 3 lands, and the
backend already reports the underlying data problem.

### Task 3 — Verify

- `cd frontend && npm test -- --run` (the two new tests now pass)
- Mutation check: revert one try/catch to `if (!move) break`, confirm red, restore.
- `npm run lint`
