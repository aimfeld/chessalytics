<objective>
Give `scripts/remote_eval_worker.py` an ordered list of backend targets so a worker drains
prod first and only falls through to the benchmark backend on :8001 when prod has nothing to
do, with strict per-claim prod priority.

Purpose: this is what lets the benchmark tranche consume the fleet's genuinely spare capacity
without ever standing in front of prod work.

Output: a `_CycleOutcome` return shape on `_run_cycle`, a `_BackendTarget` list built once in
`run_worker`, `--fallback-url` / `--fallback-token` CLI flags, and routing tests.
</objective>

Promote the worker's identity model from a single base URL to an ordered list of backend
targets, per the `<assumption_delta_decision>` recorded in `212-01-PLAN.md`.

Add a frozen dataclass `_BackendTarget` with fields `base_url: str`, `token: str`, and
`label: str` (used only in log lines, e.g. `primary` / `fallback`, so a tailed worker log
shows which backend a claim came from). Add
`_build_backend_targets(base_url, token, fallback_url, fallback_token) -> list[_BackendTarget]`
returning a one- or two-element list, with the prod target always at index 0. When
`fallback_token` is None but `fallback_url` is set, the fallback target reuses the primary's
resolved token — document that default in the flag help text so an operator who wants distinct
tokens knows they must pass one.

Change `run_worker`'s signature to take `targets: list[_BackendTarget]` in place of
`base_url` / `token`, and construct one `httpx.AsyncClient` per target inside a
`contextlib.AsyncExitStack` (the existing construction is `async with httpx.AsyncClient(...)`,
which does not generalize to N clients). Each client keeps today's exact shape: `base_url` from
its target, `headers={"X-Operator-Token": target.token, "X-Worker-Id": worker_id}`, and
`timeout=HTTP_TIMEOUT_S`. Never mutate `.base_url` on an existing client and never reuse one
client for two URLs — `base_url` and the auth header are fixed at construction, and mixing
clients mid-cycle would break lease-to-submit affinity.

Change `_run_loop` to take `clients: list[httpx.AsyncClient]` instead of `client`, and restructure
its per-iteration body: run `_run_cycle` against `clients[0]` with `idle_sleep=0` semantics
suppressed for all but the last target (see below); if the returned outcome has
`did_work=True`, that cycle is finished — do not touch any later client. If `did_work=False`,
advance to the next client and run its complete ladder. If `_run_cycle` raises and
`_is_expected_transient(exc)` is true, treat that target as no-work and advance to the next
client in the same cycle (D-14: the fleet keeps working through a prod outage rather than
idling), while still feeding the exception to the existing `_handle_transient_failure` streak
tracking so a sustained primary outage escalates exactly one Sentry event as it does today. A
non-transient exception keeps today's behavior: captured to Sentry immediately, and re-raised
when `not loop`.

Handle the idle sleep carefully. Today the sleep lives inside `_run_cycle`'s rung-5 all-204
tail. With two targets that would sleep twice per fully-idle cycle, doubling the idle latency
and breaking the T-146-06 single-sleep invariant. Add a keyword-only `sleep_when_idle: bool = True`
parameter to `_run_cycle` and pass `False` for every target except the last one in the list, so
exactly one `asyncio.sleep(idle_sleep)` is awaited per fully-idle cycle regardless of target
count. Keep the "Queue fully empty" log line on the last target only.

Add two CLI flags in `parse_args`, mirroring the existing `--base-url` / `--token` shapes:
`--fallback-url` (metavar `URL`, default None, help text explaining it is the second backend
tried only when the primary's whole five-rung ladder returns no work) and `--fallback-token`
(metavar `TOKEN`, default None, help text stating it defaults to the primary token when
omitted). Follow the existing token-resolution convention exactly: the secret is resolved after
parse in `main`, never bound as an argparse default, so it stays out of `--help` and the
namespace. Add post-parse validation alongside the existing `--workers` / `--idle-sleep` /
`--worker-id` checks: `parser.error` when `--fallback-url` is present but empty or
whitespace-only, and `parser.error` when `--fallback-token` is given without `--fallback-url`.
Update `_run_async` and `main` to build the target list via `_build_backend_targets` and pass
it to `run_worker`.
