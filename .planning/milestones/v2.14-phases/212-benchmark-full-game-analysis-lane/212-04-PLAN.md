## CONTEXT.md D-03 and RESEARCH.md both understate the derivation count — corrected here

D-03 states, and RESEARCH.md's Pitfall 2 repeats, that `is_lichess_eval_game` has **exactly one
derivation point**, `app/services/eval_apply.py:2344`, and that a second override "deeper in
the call stack" would cause drift. The premise is wrong. Re-running
`grep -rn "lichess_evals_at" app/` and `grep -rn "is_lichess" app/` at revision time finds
**seven independent derivations** of the boolean, in three syntactic shapes:

*Shape A — attribute read compared to None (4 sites):*

1. `app/services/eval_queue_service.py:290` — inside the claim path (tier-1/2 queued jobs).
   This is one of the two the *fleet* rides: it populates
   `AtomicLeaseResponse.is_lichess_eval_game` (`app/schemas/eval_remote.py:159`), which
   `app/routers/eval_remote.py:483` reads back on atomic submit and threads into the write path.
2. `app/routers/eval_remote.py:1164` — the `/flaw-blob-lease` path.
3. `app/services/eval_drain.py:750` — the tier-4b divergence-guard-parity rebuild.
4. `app/services/eval_apply.py:2344` — the best-move rebuild path (the only one CONTEXT.md
   names).

*Shape B — derived through a differently-named local off `scalar_one_or_none()` (2 sites):*

5. `app/services/eval_queue_service.py:654` — `_claim_tier3_derived`'s Step-2 per-game
   resolution: `is_lichess_eval_game = lichess_result.scalar_one_or_none() is not None`.
   **Tier-3 is the lane this entire phase drives** (212-01's selection gate is installed in
   `_claim_tier3_derived`), so missing this site would defeat homogenization on precisely the
   games the benchmark tranche selects.
6. `app/services/eval_queue_service.py:1007` — the tier-4b best-move lottery:
   `is_lichess_4b = lichess_at_4b.scalar_one_or_none() is not None`, a *third* variable name.

*Shape C — inline keyword argument at a read-path call site (1 site):*

7. `app/services/library_service.py:260` — `is_lichess_eval_game=game.lichess_evals_at is not
   None`, passed straight into `classify_best_move` as the "Imported-eval divergence guard
   (Quick 260717-gmg)", which suppresses the gem/great badge when our `best_cp` overrates
   lichess's authoritative post-move `%eval`.

**Why shapes B and C were missed the first time, and why that matters methodologically:**
shape B does not match a `lichess_evals_at is not None` text search at all — the attribute is
consumed one line earlier inside `select(Game.lichess_evals_at)`, and the identity comparison
lands on a `scalar_one_or_none()` result under a local named `lichess_result` / `lichess_at_4b`.
Shape C does match that text search, but sits in a module (`library_service.py`) that reads
nothing else from the eval pipeline, so a search scoped to the eval modules skips it. The
lesson is baked into Task 2's regression test below: **the test is AST-based and keys on the
assignment target, not on the source text of the expression** — that is the only formulation
that catches all three shapes and is simultaneously immune to the docstrings in
`eval_queue_service.py:184` and `eval_apply.py:593` that legitimately *describe* the old
expression in prose.

Overriding **only** site 4 would homogenize the best-move rebuild and leave the main
atomic drain/lease path still treating lichess games as lichess games — `eval_cp` would still
be preserved, the terminal donor would still be suppressed, and the tranche would buy the
Stockfish price for exactly the confounded comparison D-03 exists to remove. The failure would
be silent: the flag would be on, the code would look correct against CONTEXT.md, and the data
would be wrong.

**Site 7 additionally has a semantics bug that homogenization creates.** After a homogenized
run, `game_positions.eval_cp` for a touched game holds *our engine's* value, but D-04
deliberately leaves `lichess_evals_at` set (it is the §6 selection marker). So this reader
would keep passing `is_lichess_eval_game=True` and keep suppressing the gem/great badge under a
divergence guard whose premise — "`pos.eval_cp` is lichess's authoritative post-move `%eval`" —
no longer holds. Routing it through the helper fixes the semantics for free. Note this is a
*read* path: with the flag off (prod, always) the behavior is byte-identical, and the benchmark
instance serves no analysis board, so this is a correctness repair rather than a UI change.

**Correction adopted (D-03's intent preserved, its premise fixed):** introduce ONE helper,
`derive_is_lichess_eval_game(lichess_evals_at)`, in `app/services/eval_utils.py`, and replace
all seven derivations with a call to it. D-03's actual requirement — "exactly one place where
the override lives, so two overrides cannot drift" — is then satisfied for the first time
rather than assumed. No downstream reader of the variable is touched:
`eval_drain.py:836`/`:948`/`:968` and `eval_apply.py:641` all keep reading the same threaded
boolean.

**Import-cycle check (asked and answered):** there is no cycle, and there is not even a new
import edge. `app/services/eval_utils.py` imports only `math` and `typing.Literal` today — it
is a genuine leaf, importing nothing from `app.services`, `app.repositories` or `app.models`.
Adding `app.core.config` to it is safe because `app/core/config.py` itself imports only
`typing`, `dotenv` and `pydantic_settings`. And `app/services/library_service.py:63` **already
imports from `app.services.eval_utils`** (it pulls `eval_cp_to_expected_score` /
`eval_mate_to_expected_score` for `_build_eval_series`), so site 7's fix extends an existing
import statement rather than creating a new dependency. Same for the other six modules: adding
the helper to an existing leaf import is edge-free in every case.

This changes no locked decision. D-03, D-04 and D-05 stand exactly as written; only the count
of edit sites changes — from D-03's stated one, to the four this plan first reported, to the
seven confirmed here.
