Implement `tranche_status(db_url, tranche) -> TrancheStatus` returning a small dataclass or
TypedDict carrying, split by `lichess_arm`: `selected`, `full_evals_done`, `full_pv_done`,
`best_moves_done`, `blobs_done`, and `snapshot_rows` (rows in
`benchmark_lichess_eval_snapshot` for that tranche's lichess arm). Every count is an exact
`COUNT(*)` over `benchmark_selection bs JOIN games g ON g.id = bs.game_id` filtered on
`bs.tc_tranche = :tranche`, with `FILTER (WHERE g.full_evals_completed_at IS NOT NULL)` style
aggregate filters so the whole block is one query rather than five round trips. Never read
`pg_class.reltuples` or any other planner estimate — the tranche's numbers are the artifact a
data story cites, and an estimate would be wrong by a few percent in exactly the way nobody
would notice.

`status` prints a human-readable block: the six counts, a percent-complete derived from
`best_moves_done / selected` (guarding division by zero when `selected` is 0), and the
`lichess_arm` split. After the counts, print the Maia guardrail line (D-12: `status` surfaces "Maia loaded" as an
explicit operator check rather than leaving it to be inferred from DB completion columns after
the fact): when `full_pv_done > 0`
and `best_moves_done == 0`, print a clearly-marked warning stating that this is the
Maia-absent signature — the local backend is producing PV but never stamping
`best_moves_completed_at`, `_build_best_move_candidates` returns an empty list for both "Maia
ran, zero candidates" and "Maia absent" so row counts alone cannot distinguish them, and the
operator should check the :8001 startup log rather than wait. Suppress the warning when both
counts are zero, since an unstarted tranche is not a failure.

Implement `write_record_report(db_url, tranche, now) -> Path` writing
`reports/benchmark-lane/benchmark-lane-{tranche}-YYYY-MM-DD.md`, creating the directory with
`mkdir(parents=True, exist_ok=True)`. Take the timestamp as a parameter rather than calling
`datetime.now()` inline so the test can pin the filename. Content: a first line carrying the
date (mirroring the `benchmarks-latest.md` convention), then the `tranche_status` counts as a

`game_flaws` rows, and `game_best_moves` rows, each joined through `benchmark_selection`. Then
a short provenance section stating which arm's evals came from which source and naming
`benchmark_selection.lichess_arm` as the split key. Re-running on the same day overwrites that
day's file; do not append.
