<objective>
Split `useBotGame()`'s stateful orchestration into sibling hooks so the hook drops from 544
counted lines toward the 200-line hard limit, with the 167-test oracle proving the bot-game
session behaves identically.

Purpose: this file has the widest oracle of the four in scope (167 tests across five modules,
the highest test-to-size ratio) and a named return interface — `UseBotGameState` at line 223,
26 fields, destructured by name in `Bots.tsx` and asserted by name in the hook tests. That
combination makes it the safest place to establish the phase's hook-extraction pattern before
`Analysis.tsx`. It also has a specific trap: `runBotTurn` is stored in `runBotTurnRef` so a
deferred caller always invokes the latest closure without becoming an effect dependency; a
split that returns `runBotTurn` directly reintroduces the stale-closure bug that ref exists to
prevent.

Output: four (or five) sibling hooks under `src/hooks/`, `useBotGame` reduced to init/resume,
state, the sub-hook wiring and the unchanged 26-field return, and a recorded two-way mutation
proof.
</objective>
