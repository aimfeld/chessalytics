# Phase 190 — UI Design Contract

> Visual and interaction contract for Train Page + Solve Loop. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Consumed by gsd-planner (task drafting) and gsd-executor (implementation source of truth).

Scope: `/train` route (start/resume/completed states), the full session solve loop (guess → move → grade → reveal), the score screen, and nav wiring on all three surfaces. Backend endpoints and schema are Phase 189 (shipped) plus two small additive fields this phase's plan must add (`TrainPuzzle.last_move_uci`, `PuzzleRevealResponse.pv`) — see `190-RESEARCH.md` Pattern 1. No schedule settings, no streak/celebration UI (Phase 191).

## Color

60/30/10 split, using the app's existing forced-dark tokens — no new base palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `oklch(0.145 0 0)` (near-black charcoal) | Page background behind the start screen and solve loop |
| Secondary (30%) | `--card` `oklch(0.205 0 0)` | Puzzle/board card, reveal panel surface, start-screen card |
| Accent (10%) | `--brand-brown` `#8B5E3C` (Button `variant="default"`) | Reserved for: the Start/Resume-session button, the reveal's Next-puzzle button, and the score screen's "Train again" CTA. **Nothing else.** |
| Destructive | `--destructive` | Not used this phase — Train's solve loop has no delete/destructive action (the delete-all warning copy is Phase 189/191's concern per `190-CONTEXT.md` Deferred Ideas) |

Accent reserved for: Start/Resume-session button, Next-puzzle button, post-session "Train again" CTA — **not** the two guess buttons (D-05 renders those as neutral toggle chips, `variant="outline"`/`variant="brand-outline"`, so the pair never competes visually with the single high-emphasis CTA; the selected guess gets a `brand-brown-light` ring, not a solid fill).

### New semantic tokens this phase adds to `frontend/src/lib/theme.ts`

Reuse existing hue families (per the codebase's established "alias, don't invent" convention — see `GAUGE_ZONE_COLORS`/`ZONE_*` precedent) rather than introducing new hues:

```typescript
// Train verdict colors (D-10) — alias the existing WDL palette so "correct"/
// "incorrect" reads with the same green/red the rest of the app already uses.
export const TRAIN_VERDICT_CORRECT = WDL_WIN;    // oklch(0.50 0.14 145) — green
export const TRAIN_VERDICT_INCORRECT = WDL_LOSS; // oklch(0.50 0.15 25)  — red

// Train score-screen rating bands (SOLV-07: green/yellow/red).
// Green/red alias the same WDL hues; yellow is new (amber, same lightness/chroma
// family as SEV_INACCURACY but not identical — SEV_INACCURACY is reserved for
// the flaw-severity taxonomy elsewhere and must not be silently repurposed).
export const TRAIN_RATING_GREEN = WDL_WIN;
export const TRAIN_RATING_YELLOW = 'oklch(0.75 0.15 85)'; // amber
export const TRAIN_RATING_RED = WDL_LOSS;
```

Named threshold constants (SOLV-07 — pure logic, belongs in `frontend/src/lib/trainScore.ts`, not `theme.ts`):

```typescript
export const TRAIN_RATING_GREEN_MIN = 0.75;  // score/2N >= 75% -> green
export const TRAIN_RATING_YELLOW_MIN = 0.5;  // 50-74% -> yellow; below 50% -> red
```

## Component Reuse Plan (executor guidance)

Non-visual detail retained here because it directly determines what the visual contract above composes onto. Full rationale lives in `190-RESEARCH.md`; this is the condensed executor-facing checklist.

- **Board:** `ChessBoard.tsx` reused verbatim for both the solve screen and the reveal's stepper stage — orientation = `puzzle.side_to_move`, last-move highlight from the new `last_move_uci` field, click + drag input both supported already.
- **Game card + deep link (SOLV-05):** `GameCard` with its existing `analyzePly={puzzle.ply}` prop — do not build a second deep-link URL builder.
- **Grading engine (SOLV-03):** new `useTrainGradingEngine.ts`, single persistent Worker per session (not per puzzle — see RESEARCH.md Pattern 4/Pitfall 2), built on `useStockfishEngine.ts`'s single-line-search lifecycle, classified via `evalToExpectedScore`/`classifyLiveSeverity` (`frontend/src/lib/liveFlaw.ts`) and `MISTAKE_DROP` (`frontend/src/generated/flawThresholds.ts`) — never re-derive this math.
- **Best-line / tactic stepper (SOLV-05/06):** build a small new `TrainLineStepper.tsx` (SAN list + board + prev/next), NOT a `VariationTree` embed — RESEARCH.md's Pattern 3 spike recommendation stands; reuse only the portable `tacticDepthBadge`/`tacticMotifLabel` utilities from `frontend/src/lib/tacticComparisonMeta.ts`.
- **Progress bar:** a plain `h-1.5 w-full rounded-full bg-muted` track with a `bg-brand-brown` (or `TRAIN_RATING_GREEN` once the session is scored) fill — no new `Progress` primitive needs installing.
- **Nav icon:** lucide `Dumbbell` — reads clearly at `h-5 w-5` nav size, distinct silhouette from `FolderOpen`/`Bot`/`BookOpenIcon`/`TrophyIcon`, and matches the "Train" naming literally (gym/training metaphor) better than `Target` (implies precision/aim, already close to what "gem" badges connote) or `Swords` (combat framing, already owns the Bots page identity).
- **Nav wiring (NAV-01/02):** insert `{ to: '/train', label: 'Train', Icon: Dumbbell }` into both `NAV_ITEMS` and `BOTTOM_NAV_ITEMS` between the Library and Bots entries (`frontend/src/App.tsx:65-77`); add `'/train': 'Train'` to `ROUTE_TITLES`; add a `to === '/train'` branch to `isActive()` (prefix match, `frontend/src/App.tsx:115-121`); do **NOT** add `/train` to `IMPORT_EXEMPT_ROUTES` (NAV-02 — gated like Openings/Endgames). Test IDs fall out of the existing `label.toLowerCase().replace(/\s+/g, '-')` convention automatically: `nav-train`, `mobile-nav-train`, `drawer-nav-train`.
- **First-visit dot (D-16):** extend the existing `useUserFlag` chain (`FLAG_OPENINGS_VISITED` → `FLAG_ENDGAMES_VISITED`) with a new `FLAG_TRAIN_VISITED`, shown after the Endgames dot has been dismissed, on both `NavHeader` and `MobileBottomBar`.
