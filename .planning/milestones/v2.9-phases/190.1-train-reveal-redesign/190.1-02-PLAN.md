<objective>
Widen the once-per-puzzle mount search to MultiPV and keep the PV the after-move grading
search already produces, so that a single `gradeMove` call returns everything the reveal
and the board need: the best line, the played line, and the set of moves that are
genuinely good.

CONTEXT.md numbers its locked decisions D-1..D-5; this plan writes them as D-01..D-05.

Locked decisions covered: D-01 (points 1 and 2 of the search plan), D-02 (good moves come
from the existing live-flaw inaccuracy threshold, never a new cutoff).

Purpose: this is the one genuinely new search cost in the phase, and it sits on the
highest-risk file in the codebase for this work (documented StrictMode double-mount and
stale-worker lifecycle bugs). It gets its own plan so the width/budget tradeoff is
measured and the lifecycle machinery is changed once, deliberately, with the existing
regression suite as the gate.

Output: a grading engine that answers "what was best, what did you play, and which moves
were fine" from one mount search plus the one grading search that already existed.
</objective>
