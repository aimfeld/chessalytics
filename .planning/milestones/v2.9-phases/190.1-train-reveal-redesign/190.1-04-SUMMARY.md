# Phase 190.1 Plan 04: Reveal Board Arrows + Session Score Summary

**Reveal board now draws puzzle-type-capped green good-move arrows, a distinct blue played-move arrow, and a thin white game-move arrow (all sourced from the existing MultiPV grading data, none before the verdict lands), and the progress row shows the running session score top-right, surviving a resume.**

## Accomplishments

- New pure `frontend/src/lib/trainArrows.ts` — `buildTrainRevealArrows(puzzleType, goodMoveUcis, playedMoveUci, gameMoveUci, verdictLanded)` returns an empty array until the verdict lands, then up to `TRAIN_SHARP_GOOD_MOVE_ARROWS` (1) or `TRAIN_SOFT_GOOD_MOVE_ARROWS` (3) green `DARK_GREEN` arrows (in the good-moves set's own rank order), a `TRAIN_PLAYED_MOVE_ARROW`-colored played-move arrow, and an `onTop` `NEXT_MOVE_ARROW`-colored game-move arrow at a thinner width — mirrors the existing `tacticArrows.ts` pure-module precedent, unit-testable with no board render.
- New theme token `TRAIN_PLAYED_MOVE_ARROW` aliasing `BEST_MOVE_ARROW`, following the same aliasing style Phase 190 used for `TRAIN_VERDICT_CORRECT`/`TRAIN_RATING_GREEN`.
- Every arrow carries a distinct `layerKey` (`good-0`, `good-1`, …, `played`, `game`) so a coincident from-to pair across roles survives `dedupeArrowsByMove` as concentric arrows instead of collapsing.
- `TrainReveal` gained `onGameMoveUciChange` — an effect reports the reveal query's resolved `played_in_game_move_uci` up to `TrainSolveScreen` (and `null` on cleanup) without lifting the reveal query itself, preserving T-190-16's single-owner fetch-gating invariant.
- `TrainSolveScreen` threads `verdict?.puzzle_type`, `gradeResult?.goodMoveUcis`, `lastPlayedUci`, and the reported game-move UCI into `buildTrainRevealArrows` via a `useMemo`, passes the result to `ChessBoard`'s existing `arrows` prop, and resets the game-move state in the per-puzzle reset effect.
- `useTrainSession` gained `sessionSolvedCount` (`session.solved_count + solvedPositions.size`), computed and updated on the exact same tick as `sessionScore` in the solve mutation's success path — never derived from `currentIndex`, which would read stale on the very screen the score is shown.
- `TrainSolveScreen`'s progress row now shows `train-session-score` (score / max pts, max = `sessionSolvedCount * TRAIN_POINTS_PER_PUZZLE`) top-right of the existing "i of N" text, hidden until at least one puzzle has actually been scored so a fresh session never shows "0 / 0 pts"; verified to survive a resumed session's stored localStorage tally.
