<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server `SolveResponse` → reveal renderer | `item_status` and `puzzle_type` are server-computed values the client renders; the client asserts nothing new about them. |
| server-supplied FEN → `MiniBoard` / `chess.js` | A malformed or hostile FEN string reaches a board renderer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-191-10 | Denial of Service | `TrainFlawFixedBanner` FEN rendering | medium | mitigate | The FEN is parsed inside a `try/catch` before the board mounts; a parse failure collapses the thumbnail and renders text only, so a malformed FEN cannot throw out of the reveal render tree and blank the panel. Proven by the invalid-FEN and empty-FEN tests. |
| T-191-11 | Denial of Service | confetti effect on `TrainScoreScreen` | low | mitigate | The confetti call lives inside a mount `useEffect`, not the render pass, and is short-circuited entirely by `prefersReducedMotion` — a failure inside `fireWinConfetti` cannot prevent the score screen from rendering. |
| T-191-12 | Information Disclosure | banner content | low | accept | The banner renders only `puzzle.fen`, which the client already holds and displays on the solve board; it exposes no new server data and adds no request. |
| T-191-13 | Spoofing | mastery trigger | low | accept | `item_status` is computed server-side in `record_solve` from the SR ladder — the client cannot assert mastery, only render the server's verdict. Unchanged from Phase 189. |
| T-191-SC | Tampering | npm installs | low | accept | Zero new npm dependencies (`canvas-confetti`, `chess.js`, `react-chessboard`, `lucide-react` are all already installed). No install task exists, so no legitimacy audit is required. |
</threat_model>
