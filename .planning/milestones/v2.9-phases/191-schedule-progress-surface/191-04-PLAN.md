## Flagged planner assumptions

- **Mid-week settings change:** an already-materialized open session is not recomposed when the schedule changes; the new values apply from the next composition (189 D-09). CONTEXT lists this under Claude's Discretion with "keep it that simple unless planning finds a sharp edge" — no sharp edge was found.
- **Past-week re-evaluation — RESOLVED by D-18, backend landed in Plan 02 Task 3.** Settled weeks are frozen, and `PUT /train/settings` judges every elapsed unsettled week with the OLD schedule before the new one is persisted. The one remaining case, accepted explicitly in D-18: the IN-PROGRESS week is judged live, so a mid-week change prospectively re-judges only that week (the this-week hint's denominator moves). No past week is ever re-judged. This plan's UI needs no awareness of that beyond invalidating the progress query on save.
- **Debounce window:** 600ms is a planner choice; CONTEXT specifies "debounced" without a value. It also bounds how often Plan 02's settle-before-mutate runs during a chip-toggling burst.
