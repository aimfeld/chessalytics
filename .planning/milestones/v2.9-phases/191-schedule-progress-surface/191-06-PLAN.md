<objective>
Replace Phase 190's single generic "No puzzles available yet" placeholder with the two tailored cold/empty states (PROG-05, D-16) — a cold-start state that points at import and analysis, and a celebratory "All caught up!" state for an exhausted pool — then gate the phase behind a blocking human verification of the assembled Train surface.

Purpose: the two states need opposite copy and opposite CTAs, and both are reachable from the same "the composed session has zero puzzles" shape. Getting this wrong tells a user with 40 mastered items to go import games, or congratulates a user who has never had a single analyzed blunder.

Output: the two empty states, their test coverage, and a signed-off phase.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `pool_state` discriminant → rendered copy | A wrong or stale discriminant produces confidently wrong guidance (telling a user with mastered items to import games). |
| empty-state CTA → in-app route | The only navigation this plan introduces is a fixed internal route literal. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-191-24 | Spoofing | empty-state selection | medium | mitigate | The state is chosen only from the server-computed `pool_state` literal; when that value is unresolved (pending or errored) the UI falls back to the neutral Phase-190 copy rather than inferring a state from partial client data. Proven by the pending, errored and `available` fallback tests. |
| T-191-25 | Tampering | empty-state CTA target | low | mitigate | The CTA target is the hard-coded internal route literal `/library/import` rendered through react-router's `Link` — no server-supplied or user-supplied URL reaches an anchor href. |
