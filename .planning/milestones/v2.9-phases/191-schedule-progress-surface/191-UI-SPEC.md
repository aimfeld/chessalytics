## Spacing Scale

Declared values (must be multiples of 4), matching the project's established scale:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (stat chip icon + number) |
| sm | 8px | Weekday chip internal padding; gap between stat chips' icon and label |
| md | 16px | Default vertical gap between stats row / this-week line / CTA / settings block (`gap-4` throughout `TrainStartScreen`, unchanged) |
| lg | 24px | Horizontal gap between the three stat chips (streak · mastered · parked) |
| xl | 32px | — (not used by this phase's new elements) |
| 2xl | 48px | — (not used by this phase's new elements) |
| 3xl | 64px | — (not used by this phase's new elements) |

Exceptions:
- Weekday `ToggleGroupItem` chips inherit the shadcn `Toggle` default size (`h-8` / 32px tap target). This is a settings control, not a primary action, and matches every other `ToggleGroup` use in the app (filter chips) — acceptable at 32px, not raised to the 44px icon-only-button floor.
- Nav count badge is a small corner pill (`h-4 min-w-4`, ~16px) sized to sit inside the existing notification-dot corner slot — it is a passive indicator, not a tap target of its own (the whole nav `<Link>` is the tap target).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 14px (`text-sm`) | 600 (semibold) | 1.5 |
| Heading | 20px (`text-xl`) | 600 (semibold) | 1.2 |
| Display | 28px (`text-[1.75rem]`) | 600 (semibold) | 1.2 |

Exactly 2 weights (400/600) and 4 sizes (14/16/20/28), matching the existing Train components (`TrainScoreScreen`'s `text-[1.75rem]` score total is the Display precedent; `text-xl font-semibold` headings match `TrainTitle`/`TrainScoreScreen`; `text-sm font-semibold` matches every existing stat/hint line). `text-base` (16px/400) is used only for longer prose sentences (e.g. empty-state subtitles), never for numbers or labels. No `text-xs` anywhere in this phase's new UI — the nav badge number and weekday chip labels ("Mo"/"Tu"/…) render at `text-sm`, overriding shadcn `Badge`'s baked-in `text-xs` exactly as `TrainStartScreen`'s existing Beta badge already does (`className="text-sm"`).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (existing CSS var) | Page background |
| Secondary (30%) | `bg-background` + `border-border` cards/panels (no new card chrome introduced — the stats row and settings block sit directly on the page background like the rest of `TrainStartScreen`) | Stat-chip grouping, settings block |
| Accent (10%) | Flame progress colors (new, see below) + `brand-brown-highlight` celebration tint | Streak flame icon, "Flaw fixed!" banner, green-session confetti |
| Destructive | `--destructive` (existing) | Delete-all confirmation button (unchanged — copy-only edit) |

Accent reserved for:
1. **Streak flame icon** (lucide `Flame`) in the stats row — three new named colors in `theme.ts` (add, do not hardcode):
   - `TRAIN_STREAK_FLAME_MINIMUM = 'oklch(0.55 0.03 85)'` — barely-lit ember (low chroma, same hue family as the amber rating color)
   - `TRAIN_STREAK_FLAME_MEDIUM = TRAIN_RATING_YELLOW` (alias — reuse the existing amber, `oklch(0.75 0.15 85)`)
   - `TRAIN_STREAK_FLAME_MAXIMUM = 'oklch(0.62 0.20 40)'` — hot orange-red, highest chroma, hue shifted warmer
   Rendered sizes step up with state too: minimum `size-5` (20px), medium `size-5`, maximum `size-6` (24px) — the flame visibly grows as well as brightens.
2. **"Flaw fixed!" celebration banner** — uses the existing brand tokens (`bg-brand-brown-highlight/40`, `border-brand-brown-light/60`, `text-brand-brown-hover`), never `FLAWCHESS_ENGINE_ACCENT` (that gold is reserved for the FlawChess Engine's own identity on the analysis board — reusing it here would visually conflate the two features).
3. **Green-session confetti** — `CONFETTI_COLORS` / `fireWinConfetti()` verbatim, no new palette.
4. **Nav count badge** — the existing red-500 "notification" family already used for `library-notification-dot` / `openings-notification-dot` / etc. (`bg-red-500`, white text) — kept as a Tailwind utility class at the call site exactly like its dot precedent (not promoted to `theme.ts`, matching how the existing dots are implemented), so the new numeric badge reads as the *same* attention-signal vocabulary as the rest of the nav, not a new one.

No new destructive color — the delete-all button variant/color is unchanged (copy-only edit, D-folded-todo).

## Visual Hierarchy

**Primary visual anchor: the stats row** (lit `Flame` icon + streak number, flanked by the mastered and parked counts). It sits at the top of the Train start screen and is the largest/highest-chroma element on the page — the flame is the only saturated accent above the fold, and the streak number renders at Display size (28px/600) while everything below it is Heading or smaller. This encodes D-13's intent: progress is the motivational headline, the "Start session" CTA is the second read, and the schedule settings block is the third (deliberately quiet, `text-sm` labels on the page background with no card chrome).

Reading order down the screen: **stats row → this-week hint → primary CTA → settings block**. On mobile the same vertical order holds (single column throughout); nothing reflows into a side rail.

## UI Considerations

Generated by the ui-consideration-probe over 11 declared UI surfaces, with agent-confirmed element-kind
overrides (E2 → `static-content`; E8 → `media`; E9/E10 → `+interactive-control`; E11 → `+form` — the
heuristic classifier left E2/E8 unclassified and treated the empty states and the confirm dialog as

**Coverage: 46 applicable — 43 covered, 3 backstop, 0 unresolved, 0 unclassified.**

Empty-state and error-state *copy* is not restated here — it lives in `## Copywriting Contract` and is
referenced by row. This section covers shape-rooted STATE behavior.

### E1 — Progress stats row (streak flame · mastered · parked)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ covered | Zero-session user: flame renders unlit (`text-muted-foreground` `Flame`, `size-5`), **no streak number** (D-03 bans a literal "0-week streak"), "0 mastered", "0 parked". The row never disappears — it reads at zero. D-16's two empty states replace the *whole* screen, not this row. |
| loading | ✅ covered | Muted skeleton in the row's slot while `GET /train/progress` is in flight. Zeros are never rendered during load — a false "0 mastered" for a user with 40 mastered items is a correctness bug, not a cosmetic one. |
| error | ✅ covered | `isError` branch renders the mandatory CLAUDE.md copy (see Copywriting Contract) inline in the stats slot. The CTA and settings block below stay fully usable — progress failing to load must never block starting a session. |
| populated | ✅ covered | Three chips at 24px gaps: lit flame + "{N}-week streak", "{N} mastered", "{N} parked — too hard for now". Counts are small integers bounded by realistic pool size; no reflow at two digits. |
| partial | ✅ covered | Not reachable: streak, flame state, mastered and parked all come from the single `GET /train/progress` response (D-05, computed on the fly), so the row is all-or-nothing. There is no half-loaded variant to design. |
| overflow | ✅ covered | The three chips are a flex row that **wraps** rather than truncates at 320px (parked's "— too hard for now" is the longest chip). No ellipsis on any count. |
| zero-one-many | ✅ covered | "1-week streak" vs "{N}-week streak" (singular handled, not "1-weeks"). "1 mastered" / "1 parked" read correctly without an explicit plural branch. Zero = the `empty` row above. |

### E2 — This-week hint line

| Category | Status | Resolution |
|----------|--------|------------|
| overflow | ✅ covered | Single `text-sm` line directly under the stats row; wraps to two lines at 320px rather than truncating. Longest realistic string ("This week: 7 of 7 sessions") fits on one line at ≥360px. |
| long-text | ✅ covered | Fixed strings with only small-integer interpolation (session counts, bounded by 7 scheduled days). No user-supplied text, no dates. |

### E3 — Weekday picker (7-chip `ToggleGroup`, auto-saving)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ covered | All-off is a **valid** state meaning "train anytime" (189 D-07, carried forward — not re-decided). No validation error, no forced minimum selection; the this-week hint switches to the unscheduled count-based copy. |
| loading | ✅ covered | **Chips render disabled/muted until `GET /train/settings` resolves** (user decision, this session). Because there is no Save button (D-10), an interactive control seeded with a placeholder default would let a tap auto-persist a value the user never chose. Disabled-until-known closes that race. |
| error | ✅ covered | A failed `PUT /train/settings` shows "Couldn't save. Try again." in the autosave-indicator slot. The chip selection **does not silently revert** — the UI keeps showing what the user chose, and a retry re-sends that same selection. |
| partial | ✅ covered | Not reachable: the weekday selection is a single `weekday_mask` integer (0–127), always complete. Every subset of the 7 bits is a legal value. |
| long-text | ✅ covered | Fixed 2-letter abbreviations (Mo/Tu/We/Th/Fr/Sa/Su). No dynamic or localized text, so no truncation or reflow risk across the 7-chip row. |

### E4 — Puzzles-per-session segmented picker (6 / 12 / 18 / 24)

| Category | Status | Resolution |

### E5 — Nav count badge (desktop header + mobile bottom bar)

| Category | Status | Resolution |
|----------|--------|------------|
| loading | ✅ covered | Badge is **absent** while the progress query is in flight — the same "absent until known" behavior as the existing `library-notification-dot` / `openings-notification-dot`. Never a spinner or placeholder inside nav chrome. |
| error | ✅ covered | **Silently absent on error** (user decision, this session) — no error affordance in the nav. The failure surfaces on the Train page itself (E1's `error` row), where the user can actually act on it. Badge state is derived, never blocking. |
| overflow | ✅ covered | Pill uses `min-w-4` (not a fixed width) so it grows to fit two digits without clipping, plus a defensive `99+` cap. Realistic values stay ≤24 (max puzzles-per-session preset), so the cap is belt-and-braces, not an expected path. |
| long-text | ✅ covered | Numeric content only (≤2 digits + the `99+` cap). No text to truncate. Mobile: the badge sits at the existing dot's corner slot (`top-1.5 right-[30%]`, `h-4 min-w-4`) and must not collide with the adjacent "Bots" tap target at 320px — fix layout, never shrink the label type. |

### E7 — "Flaw fixed!" celebration banner (in the reveal comeback-hint slot)

| Category | Status | Resolution |
|----------|--------|------------|
| empty | ✅ covered | The banner renders **only** on a `SolveResponse.item_status` transition to `mastered`. Otherwise the slot shows Phase 190's normal comeback hint. There is no empty-banner state. |

| Category | Status | Resolution |
|----------|--------|------------|
