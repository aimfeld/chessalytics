## Tests

### 1. Privacy Policy vs `herring_pool` retention

expected: A decision between (a) accept retention + reconcile Privacy.tsx wording, or (b) add a `herring_pool` purge step to the manual account-deletion runbook.

result: **passed — resolved 2026-07-28 by the project owner.** Option (a): accept the
retention, and explicitly do **not** change `Privacy.tsx`'s wording. Rationale: what
survives account deletion is a single chess position unlinked from any game or user, which
is acceptable.

Verified against the live schema rather than assumed: the composite FK `(game_id, user_id)
-> games(id, user_id)` with `ondelete="SET NULL"` nulls **both** columns, so a post-deletion
row retains only `fen`, `ply`, `mover_color`, `phase`, `arriving_move_uci`, `ladder`,
`source_played_at` and `created_at` — no user reference and no game reference.

This confirms D-01's intent and **narrows** 192-01's prohibition rather than violating it:
the prohibition forbids widening the trade into a policy of retaining *identifiable* pool
rows against a deletion or opt-out request, and a de-identified position is not that.

Residual note, accepted with the decision: `source_played_at` retains a "when the original
game was played" timestamp. Not identifying on its own, but it is the only provenance trace
that survives. No action taken.

why_human: This is a product/legal judgment about data-retention policy versus a stated
privacy commitment — no grep or test can settle it. It is genuinely contested inside the
phase's own artifacts: `192-01-PLAN.md`'s `must_haves.prohibitions` explicitly warns that
the trade "must not be widened into a policy of retaining pool rows against an
account-level deletion or opt-out request", while D-01 in `192-CONTEXT.md` (user-locked)
says the pool row survives "regardless of what happens to the source account". None of the
five phase SUMMARY.md files mention or resolve the tension.

no immediate exploit path: account deletion is manual and email-driven today, so nothing
is silently mis-honoring a self-service request in production right now.
