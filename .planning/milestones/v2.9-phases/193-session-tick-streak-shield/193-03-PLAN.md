<flagged_assumption>
## Flagged assumption — SCHD-02 edge behavior (edge probe: UNRESOLVED)

The edge-coverage probe classified one SCHD-02 row as `unclassified` and it is deliberately left
**unresolved** rather than auto-backstopped or dropped. Stating the assumption plainly so a human
can contradict it:

**Assumed:** when a session is open, unfinished, AND its window has already expired, the D-10
carve-out does **not** apply — `badge_visible` falls back to the plain D-09 scheduled-day test.
Rationale: `_open_unfinished_exists` returns False for an expired session (it checks
`is_session_expired(open_session.expires_on, today)` first), and `get_waiting_puzzle_count`'s
branch 1 already skips expired-but-still-`open` rows the same way. So on an unscheduled day after
a session's window closed, the badge is hidden even though an `open` row still exists in the DB
with unsolved puzzles.

**Why this is the defensible default:** the expired session is already a D-08 miss and will be
flipped to `'expired'` by `expire_stale_sessions` on the next composition. Keeping its badge alive
would nag the user toward a session they can no longer complete for credit, which is the exact
pressure mechanic D-09 exists to remove.

**Contradict it if:** the user wants the badge to survive window expiry as a "you can still finish
this for practice" cue. That would be a one-line change to `_open_unfinished_exists` (drop the
expiry check) plus a new test, and it would need a matching decision about whether a
window-expired completion should still earn its D-07 pip. Raised at the Task 3 human-verify
checkpoint.
</flagged_assumption>
