<objective>
Stand up the Train backend skeleton end-to-end and the pure interval-ladder scheduler that drives it.

Purpose: prove the whole Train architecture on one real path before any horizontal expansion — a
qualifying own blunder in PostgreSQL becomes a drill item, gets materialized into a frozen session,
and is served over HTTP with no answer key in the payload. Everything Phases 190/191 consume hangs
off the contracts fixed here.

Output: four new tables (`drill_items`, `drill_sessions`, `drill_solves`, `train_settings`) with an
applied Alembic migration; `train_scheduler.py` (pure, zero I/O), `train_pool.py`,
`train_repository.py`, `schemas/train.py`, `routers/train.py` registered in `app/main.py`; passing
scheduler unit tests and an end-to-end router test.
</objective>

<planner_decisions>
Decisions this planner made under CONTEXT.md "Claude's Discretion". They are binding for the whole
phase — later plans implement against them, they are not re-litigated per plan.

- **P-01 — `best_move` is NOT in the pre-attempt payload.** POOL-10 reads plainly: the pre-attempt
  payload carries no answer key. 189-RESEARCH.md Pitfall 5 assumed `best_move` had to ship
  pre-attempt for the client's exact-match fast path; it does not. The client already runs the
  vendored Stockfish WASM to grade any non-exact move, and that same search yields the best move
  and its eval, so the exact-match shortcut is a latency optimization, not a requirement. Cost:
  the client always pays the ~1s eval. Benefit: POOL-10 holds literally.
  **Phase 190 note:** the solve loop must grade entirely from its own engine output.
- **P-02 — `correct_guess` is computed server-side, not submitted.** The client submits the raw
  user `guess` ("critical" / "several"); the backend compares it to the live blob classification at
  record time. This is what keeps the sharp/soft ground truth out of the pre-attempt payload.
- **P-03 — puzzle FEN is reconstructed from `games.pgn`.** `game_flaws.fen` is `board_fen()`
  (piece placement only — see its model docstring), so it loses castling rights and en-passant.
  A drill puzzle needs legal-move generation, and red herrings have no stored FEN at all. One
  helper, `full_fen_at_ply(pgn, ply)`, serves both sources.
- **P-04 — `SHARP_GAP_ES = MISTAKE_DROP`.** The seed defines a sharp puzzle as one where second-best
  is itself a mistake. That is exactly `flaws_service.MISTAKE_DROP` (0.10), the same C2 gate
  `classify_best_move` uses. No new magic number is introduced.
- **P-05 — `WINNABILITY_FLOOR_ES = 0.20`** (low end of the seed's ~20-25% band),
  `LADDER_DAYS = {0: 0, 1: 3, 2: 10}`, `MASTERY_STREAK_THRESHOLD = 3`, `PARK_FAIL_THRESHOLD = 3`,
  `HERRING_SHARE = 0.25` with `herring_slots = floor(N * HERRING_SHARE)` and
  `sr_slots = N - herring_slots` (the SR side absorbs the remainder: N=12 → 9 SR + 3 herrings).
- **P-06 — reveal is a separate post-attempt GET**, not an unlock flag on an already-fetched object
  (189-RESEARCH.md Open Question 3 recommendation).
- **P-07 — `drill_solves` is pre-materialized at composition** (189-RESEARCH.md Pattern 6): one row
  per selected puzzle, `solved_at` NULL until attempted.
</planner_decisions>

**Models (4 files, one class each, `__all__` export, module docstring naming Phase 189 + the
decision IDs each column encodes).**

Per D-01 no drill table gets a snapshot column: `best_move`, `pv` and the sharp/soft classification
are always live-joined from `game_positions` / `game_flaws` at serve time, so none of the four models
below may add a cached copy of them.

`drill_items` — composite PK `(user_id, game_id, ply)` mirroring `game_flaws`. `user_id` FK
`users.id` ondelete CASCADE; `game_id` FK `games.id` ondelete CASCADE; `ply` SmallInteger, plain
column. Per D-02 there is NO ForeignKeyConstraint to the flaw table — state that explicitly in the
module docstring with the reclassify-delete rationale. Columns: `status` SmallInteger (IntEnum
`DrillStatus`: ACTIVE=0, MASTERED=1, PARKED=2) server_default "0"; `streak` SmallInteger default 0;
`due_date` Date not null; `fail_count` SmallInteger default 0; `ever_correct` Boolean default false;
`created_at` DateTime(timezone=True) server_default func.now(). Constraints:
`CheckConstraint("status IN (0, 1, 2)", name="ck_drill_items_status")`,
`CheckConstraint("streak >= 0", name="ck_drill_items_streak")`,
`CheckConstraint("fail_count >= 0", name="ck_drill_items_fail_count")`,
`Index("ix_drill_items_user_status_due", "user_id", "status", "due_date")`.

`drill_sessions` — surrogate `id` PK; `user_id` FK `users.id` ondelete CASCADE (D-04: users only,
no game FK, survives a game wipe — say so in the docstring); `session_date` Date; `status` Text
with `CheckConstraint("status IN ('open', 'completed', 'expired')", name="ck_drill_sessions_status")`
(TEXT+CHECK per CLAUDE.md for a low-volume domain column); `puzzle_count` SmallInteger;
`expires_on` Date; `started_at` / `completed_at` DateTime(timezone=True), completed_at nullable.
Add a partial unique index `uq_drill_sessions_user_open` on `(user_id)` with
`postgresql_where=text("status = 'open'")` — this is the D-12 single-open-session guarantee.

`drill_solves` — composite PK `(session_id, position)`. `session_id` FK `drill_sessions.id` ondelete
CASCADE; `position` SmallInteger (0-based frozen order); `user_id` FK `users.id` ondelete CASCADE;
`game_id` FK `games.id` ondelete CASCADE; `ply` SmallInteger; `source` SmallInteger (IntEnum
`DrillSource`: SR_ITEM=0, RED_HERRING=1) with `ck_drill_solves_source`; `guess` SmallInteger
nullable (IntEnum `DrillGuess`: SEVERAL=0, CRITICAL=1) with `ck_drill_solves_guess`;
`correct_guess` Boolean nullable; `correct_move` Boolean nullable; `played_move` String(5) nullable;
`solved_at` DateTime(timezone=True) nullable (NULL = not yet attempted, P-07). Add
`UniqueConstraint("session_id", "game_id", "ply", name="uq_drill_solves_session_puzzle")`.

`train_settings` — PK `user_id` FK `users.id` ondelete CASCADE; `timezone` Text not null
server_default "UTC"; `weekday_mask` SmallInteger not null server_default "0"; `puzzles_per_session`
SmallInteger not null server_default "12". Constraints
`ck_train_settings_weekday_mask` (`weekday_mask BETWEEN 0 AND 127`) and `ck_train_settings_puzzles`
(`puzzles_per_session BETWEEN 1 AND 50`).
