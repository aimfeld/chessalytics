  <action>
Add the D-15 tight gate and the D-17 degenerate exclusion to `herring_stmt`. Both are query-time
predicates over the raw stored ladder — nothing here may be precomputed into a column.

**Best-line expected score.** Read PV[0]'s `cp` and `mate` out of the ladder with a JSONB path
extraction on index `0`, cast to integer, and convert with the existing
`expected_score_sql(cp, mate, HerringPool.mover_color)`. The stored cp/mate are white-POV (house
`_score_to_cp_mate` convention) and `mover_color` is the side to move on the board the generator
searched, so this yields mover-POV expected score with no ply-parity re-derivation anywhere in the
query. Do not declare a second sigmoid and do not import a new conversion — `expected_score_sql`
is the single shared implementation, and a second one risks silent disagreement at exactly the
threshold boundary this gate lives on.

**Qualifying tally.** Build a correlated scalar subquery: `SELECT count(*)` over
`jsonb_array_elements(HerringPool.ladder)`, where each element's expected score (same conversion,
same `mover_color`) satisfies `best_es - element_es < INACCURACY_DROP`. Require the count to be
at least `HERRING_MIN_QUALIFYING_MOVES`.

The comparison is **strict** `<`, and that direction is load-bearing rather than arbitrary:
`flaws_service` classifies a drop as an inaccuracy at `drop >= INACCURACY_DROP`, so a move exactly
`INACCURACY_DROP` below the best is already an inaccuracy and is therefore not one of the "several
fine moves". Record that reasoning in a comment at the predicate.

PV[0] itself always satisfies the predicate (gap 0.0 to itself), so a count of 2 means "the best
plus one genuinely fine alternative" — state that in the docstring so nobody later reads the
constant as "two alternatives besides the best" and moves it to 3.

Note explicitly, in a comment, that **no `jsonb_typeof` shape guard is added here**, and why: the
`ck_herring_pool_ladder_shape` CHECK makes "a 5-element JSON array" a write-time structural
invariant of every stored row, so `jsonb_array_elements` is total on this column. Adding a type
guard AND-ed with an array function in the same WHERE clause is the documented live crash pattern
this codebase already hit (see `answer_key_present`'s docstring — Postgres does not guarantee
AND-clause evaluation order). Enforce at write, never re-check at read.

**Degenerate exclusion (D-17).** Require `best_es - pv4_es >= HERRING_DEGENERATE_MIN_GAP_ES`,
reading PV[4] by JSONB path index `4` through the same conversion. This is precisely the
discriminator MultiPV-5 buys over the rejected boolean-count design: a dead-drawn or totally
winning position where even the fifth-best move is fine is not a judgement test. Keeping it at
query time (rather than filtering at generation) is what makes it retunable and what lets a later
review check whether it was too aggressive.

**Ordering.** Make the ORDER BY a total order:
`(qualifying_count >= HERRING_PREFERRED_QUALIFYING_MOVES) DESC` (D-15's "preferring 3+", a
preference and not a filter — rows with exactly 2 must still be reachable),
then `HerringPool.source_played_at.desc().nullslast()`, then `HerringPool.id.asc()`.

Record in the docstring why recency now reads off `source_played_at` rather than a `games` join:
SEED-120 carries the recency ordering forward, but a global pool cannot join `games` for it
without reintroducing exactly the link that D-01 lets null out. Copying `played_at` onto the row
at generation time preserves the recency contract and survives source-game deletion — the same
reasoning D-03 already applies to the FEN and arriving move. This is a deliberate resolution, not
a dropped requirement.

Finish the docstring rewrite started in Plan 01: it must state the amended POOL-03 contract
(MultiPV-5-confirmed, phase-balanced global pool, winnability handled at generation, recency
ordering, no repeats until exhausted, no SR bookkeeping), the loose-generation / tight-query split
with both constants named, the strictness direction and why, the degenerate bound and why it is
query-time, and the `exclude_served` exhaustion contract. It must not describe the superseded
sourcing in any form — a later audit reading this docstring must not be able to mark the old
definition green.
