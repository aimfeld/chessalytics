worse than a missing footer.

herring outright, so its absence leaks nothing the user is not already told.

`number | null` and needs no change; the call site's existing `verdict !== null ? puzzle.game_id : null`
ternary just needs to stay type-correct once `puzzle.game_id` can itself be null.

**`TrainSolveScreen.tsx` — D-09 Analyze visibility.** Wrap only the Analyze `<Button asChild>`
block in a `puzzle.game_id !== null` condition. Hide it — remove it from the DOM — rather than
disabling it. Solution and Next render unconditionally, exactly as now. `buildGameAnalysisUrl`
keeps its current signature and needs no widening, because the call site is now conditional and
can never pass null.

Keep the row's flex layout intact when Analyze is absent: the two remaining buttons each carry
`flex-1`, so they will expand to fill the row, which is the correct behavior and needs no special
casing. Verify this on the mobile layout too — CLAUDE.md requires a change to a component with
desktop and mobile surfaces to be applied to both; check whether this action row has a duplicated
mobile variant before considering the change complete.

Preserve every existing `data-testid` and `aria-label`. Do not introduce any font size below
`text-sm`.

**No backend work.** D-09 is explicit that the Analyze deep-link needs none:
`GET /api/library/games/{game_id}` is deliberately not owner-scoped (any authenticated user may
inspect any game by URL, for scouting and sharing — verified at `app/routers/library.py:137`), so
`/analysis?game_id=X&ply=Y` already resolves for a cross-user herring. Do not add an
authorization change, an ownership check, or a new endpoint here.
