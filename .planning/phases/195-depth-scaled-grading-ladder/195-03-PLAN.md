<objective>
Rekey the grade cache from `fen` to the composite `(fen, grading depth)` so the ladder cannot
make a transposed position's grade depend on which visit order reached it first.

This is bug PREVENTION shipping alongside the ladder, not a performance improvement, and it must
not be reported as one. Without it, the moment Plan 05's rungs stop being flat, a position
reachable at two different tree depths would be graded at whichever depth happened to arrive
first and then served from cache to the other — a real ENGINE-07 determinism violation that no
existing test would catch.

The identity decision behind this plan (`fen` demoted, `(fen, depth)` promoted, no
`fen`-only read path retained) is recorded in Plan 01's `<assumption_delta_decision>` block.
The invariant test in Task 1 IS that decision's companion invariant test.

Purpose: LADDER-03.
Output: a composite-keyed cache whose cross-depth non-satisfaction is asserted in both visit
orders, and whose Phase 194 LRU fix demonstrably survives the rekey.
</objective>

  <behavior>
    - Grading `(FEN, [UCI])` at depth 14 and then requesting the same `(FEN, [UCI])` at depth 10 issues a SECOND `go` — the depth-14 entry does not satisfy the depth-10 request — and the depth-10 request resolves with the depth-10 value.
