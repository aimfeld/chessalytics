<objective>
Ship the Maia WDL head as the leaf value for deep tree nodes, end to end, in both `SearchRunner`
implementations — the load-bearing engine-design change of Phase 197.

This is NOT "swap `grade()` for the WDL at the same call site". Premise correction **P-01**:
`policy(leaf.fen, …)` values the node being expanded, not its children, so there is no drop-in
substitution. What ships is **value-at-own-expansion**: past the handoff depth the node's own WDL
becomes its value, and every child created at that expansion inherits that same value, which makes
`recomputeValue(leaf)` a provable no-op at the boundary for a non-terminal child set. This is a
genuinely different backup rule from today's per-child 1-ply-lookahead Stockfish valuing — it is the
classic AlphaZero-shaped value-at-node rule, and `backup.ts`'s `BackupChild` doc comment gains a
third value provenance to say so.

Purpose: LEAF-01 (consume the already-transferred WDL, eliminate the grade call at deep nodes) and
LEAF-03 (verify — not assume — the root-relative frame invariant for the WDL path). LEAF-05's
answer is seeded here as the doc comment that explains WHY the leaf reads the ELO the `policy()`
call already requested (D-01: single-sourced from that same inference, never a second rung); the
full written argument lands in Plan 04.

Two locked consequences this plan deliberately does NOT act on. **D-03**: at a WDL leaf the value
and the priors come from the same network, so the search loses its only external check — this plan
CREATES that exposure, and Plan 03's committed Maia-blindness fixture is what makes the risk
falsifiable. **D-04**: Maia's WDL is per-ELO and low rungs compress toward 0.5, so the spread of
leaf values now varies with the search ELO in a way the ELO-agnostic lichess logistic never did;
Plan 02 measures that spread and this phase retunes no downstream threshold.

Output: a working WDL-leaf path in `mctsSearch.ts` AND `fallbackExpectimax.ts` (ENGINE-06 mirror
discipline — these must not land in different waves), a new `wdlLeafExpectedScore` with its own
frame fixture, a `usesWdlLeaf` predicate in the zero-import `gradingLadder.ts`, and a policy cache
that structurally cannot serve a policy hit with a WDL miss.

**Size note for the executor:** Task 1 is the tracer and is deliberately the largest task in the
phase — it touches nine files because a thinner slice would leave an architectural gap (a
separately-evicted WDL cache, or a WDL that never reaches the search core). Read the `read_first`
set once, extract everything needed in that pass, and do not re-read.
</objective>

The doc comment on the constant must state four things: (a) this is the tree depth at and past which
a leaf's value comes from Maia's own WDL head instead of a Stockfish `grade()` call (Phase 197
LEAF-01/LEAF-02); (b) the value `3` here is the **pre-declared first candidate**, chosen because it
is exactly the boundary where `GRADING_DEPTH_LADDER`'s three-rung `[14,14,14]` band ends and
