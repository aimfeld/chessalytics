### 4. Backstop truth — fan-out order within one user's subscriptions is irrelevant

steps: Run `send_to_user` against a multi-subscription set in several permutations of row order; compare per-subscription outcomes.
expected: Order-independent.
result: pass
source: code-inspection
evidence: |
  `push_send.send_to_user:180-207` iterates subscriptions sequentially,
  wrapping each in its own try/except so one device's failure cannot stop
  or alter another's. `send_to_subscription` builds a fresh `WebPush` and
  `WebPushSubscription` per row from that row's own endpoint/p256dh/auth —

  commutative sums, so any permutation yields identical per-subscription
  outcomes and an identical `PushFanoutResult`.

### M-1. Multi-device fan-out verified (PUSH-01 / REMIND-06) — pass

Desktop Chrome and Android Chrome subscribed simultaneously under one user
(`push_subscriptions` ids 1 and 5, distinct `fcm.googleapis.com` endpoints,
user agents `X11; Linux x86_64` and `Android 10; K`). One
`POST /api/push/dev/trigger-reminder` reached BOTH devices. This is the first
exercise of the fan-out at size > 1 — test 1 above only ever proved size 1.

### M-2. Android status-bar badge was illegible — FIXED

`push-sw.js` set `badge: '/icons/icon-192.png'`, the full-colour app logo.
Desktop ignores `badge` entirely, so this was structurally invisible to test 1
and could only ever surface on a phone. Android masks the badge to a
silhouette by ALPHA and draws it at status-bar size, where the detailed logo
became an unreadable smudge (operator-confirmed on device).

Fixed: added `frontend/public/icons/badge-96.png` — the lucide `chess-knight`
outline (the same icon the site already uses; ISC), white on transparent,
96x96 — and pointed `badge:` at it. `icon:` is unchanged; it renders large and
in colour and was never affected.

Operator chose the stroke/outline form over a filled silhouette. A filled
variant measured with more margin under aggressive downscaling (50% vs 36% ink
at 24px), but the outline is legible in simulation and matches the site's icon
style exactly. Noted because the simulation is known to run OPTIMISTIC — it
rated the old logo as passable at 6x zoom when the real device showed it as
illegible. **Re-verify on a real Android device**; if the outline still does not
read at true status-bar size, the filled variant is the fallback and needs only
a regenerated PNG, no code change.
