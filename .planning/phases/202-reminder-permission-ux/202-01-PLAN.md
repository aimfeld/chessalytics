<assumption_delta_decision>
**Noun:** *reminder reachability* — the thing the system must name in order to
answer "can we reach this user?".

**Seam:** `reminder_enabled` is **account-wide** (one row per user in
`train_settings`), while `push_subscriptions` rows are **per-device-per-browser**
and 201 D-05 fans out to all live subscriptions. This phase adds a second
reachability axis to a model that previously had one.

**Decision:** `no-change`.

**Rationale:** CONTEXT.md D-05 states the asymmetry is intended and load-bearing
for this phase's UX — an unsubscribed desktop can never be reached, so offering
the opt-in there is a genuine offer rather than a repeat. Promoting a per-device
identity to primary would require a per-device `reminder_enabled`, which nothing
in PERM-01..04 asks for and which D-07 actively argues against (the whole point
of the master toggle is one account-wide silence switch that leaves every device
grant intact).

**What would force a later promote:** the deferred per-device management list
("your devices", last-seen labels, turn reminders off for one device). That
feature needs the `last_seen_at` / device-label columns 201 D-05 deferred, and
the moment a user can disable one device independently, per-device becomes the
primary identity and the account-wide flag demotes to a global override.

**Suggested (not required) invariant test:** a contract test asserting that for
every supported entry point, `reminder_enabled` is never written `true` unless
the calling device holds a live subscription. Task 2 and 202-02 T2 already
encode this per entry point; a single shared assertion would go red the instant
a future phase reintroduces a write path that skips the subscribe.
</assumption_delta_decision>
