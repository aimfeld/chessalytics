<objective>
Prove the `reminder_intent_at` round-trip end to end — PostgreSQL column through model,
migration, Pydantic schemas, repository, router, frontend types, the `useTrainSettings`
mutation, and both existing PUT call sites — before any new UI is built on top of it.

Purpose: this is the phase's architectural spine and its single biggest cross-cutting
hazard. `TrainSettingsUpdate` is a full-replace shape (`app/schemas/train.py:219`), so a
partial rollout of the new field breaks every existing weekday/puzzle-count save with a 422
(PATTERNS.md "Pitfall 1"). Proving the whole path on one field, with the existing tests
green, is what makes Plans 02-04 safe to build in parallel and on top.

Output: a migration, a client-writable nullable timestamp column, a widened settings
contract on both sides of the API, and integration + component tests that prove the
round-trip and the loud-failure semantics.
</objective>
