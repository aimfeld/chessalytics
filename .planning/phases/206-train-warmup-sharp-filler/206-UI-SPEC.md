# Phase 206 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** this is a small UI surface — a new `'warmup'` landing kind in
`TrainStartScreen.tsx`'s `resolveLandingState` (replacing the removed `'short'` kind), and a
`source`-based rewrite of the your-game predicate at three sites in `TrainReveal.tsx` plus one
new motif-name element on the sharp-filler reveal. No new pages, no new shared components, no
new shadcn blocks. This contract governs exactly those surfaces.

## Typography

Established project values (Train already conforms to these; this phase adds no new size or
weight):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | regular 400 | 1.5 |

| Heading | 16px (`text-base`) | semibold 600 | 1.2 |

Two weights only (regular 400, semibold 600) — matches CLAUDE.md's global rule. `text-xs` is

floor. Note: `TacticMotifChip.tsx` carries a pre-existing `text-xs` exception documented in its

- **Heading (16px)** — the default (non-compact) `CardHeader` role used elsewhere in the app;
  not directly touched by this phase (Train's own cards all use `size="compact"`), listed for

- **Label (14px, semibold)** — banner headlines (mirrors `TrainReminderResurfaceBanner`'s
  `text-sm font-semibold` headline), compact `CardHeader`, button labels.
- **Body (14px, regular)** — muted prose: banner subtitle, tagline, guess-feedback prose, the
  new motif line.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` (`oklch(1 0 0)` light / `oklch(0.145 0 0)` dark) | Page background |
| Secondary (30%) | `--card` (`oklch(1 0 0)` light / `oklch(0.205 0 0)` dark) + the `charcoal-texture` `Card` surface, `bg-black/20` header bands | Card surfaces, header bands, borders (`--border`) |
| Accent (10%) | `--brand-brown` (`#8B5E3C`) | Reserved for: the primary Start/Resume CTA button (`variant="default"`, unchanged), the existing `TrainReminderResurfaceBanner`'s accent spine + its own CTA. **Not** used for the new warm-up banner (see below). |
| Destructive | `WDL_LOSS` (`oklch(0.50 0.15 25)`, `theme.ts`) | Not applicable — this phase introduces no destructive action. Listed for completeness only. |

Accent reserved for: the Start/Resume button and other pre-existing brand-accented elements
only. **Decision (Claude's discretion, per CONTEXT.md):** the new warm-up banner Card renders
**without** `accentColor` (a plain `charcoal-texture` card, no colored left spine) — it is
informational framing, not a call-to-action competing for the same 10% accent budget as the CTA
button directly below it or the reminder-resurface banner above it. Using the brand accent here
would visually equate "you're doing a warm-up" with "act now," which is the wrong emphasis.

No new hex/oklch values are introduced. Reused verbatim: `--background`, `--card`,
`--muted-foreground`, `--border`, `--brand-brown`.

## Component Specifications

### 1. `TrainStartScreen.tsx` — new `'warmup'` landing kind

**Where it slots into `resolveLandingState`:** immediately alongside the removed `'short'`
kind's old position (after the `'resume'`/`'completed'` checks, before the final `'fresh'`
fallback) — both require `solved_count === 0` and a non-empty, fully-composed session
(`puzzle_count === requested_count`, since the sharp/herring backfill guarantees a full
session per D-02/D-03). The discriminant is the server-persisted `is_warmup` boolean on
`TrainSessionResponse` (D-07) — **the client performs no arithmetic**; it is a single equality
check, matching every other branch in this function (T-191-24).

```
type LandingState =
  | { kind: 'loading' }
  | { kind: 'error' }
  | { kind: 'empty' }
  | { kind: 'completed'; ... }
  | { kind: 'resume'; ... }
  | { kind: 'warmup'; puzzleCount: number }   // NEW — replaces 'short'
  | { kind: 'fresh'; puzzleCount: number };
```

**Render shape (Claude's discretion on visual treatment):** the `'warmup'` kind renders
**everything the `'fresh'` kind renders today, plus one additional `Card`** inserted between
`TrainHeader` and the CTA `Button` — i.e. it is `'fresh'` plus a banner, not a distinct page
layout. This keeps the CTA button, streak/stats card grid, and `TrainScheduleSettings` fully
uniform between warm-up and ordinary sessions (matches the locked decision: "accrues streak and
scores exactly like any other session," so the surrounding UI should not visually distinguish
them either).

**New banner markup** (structurally mirrors `TrainReminderResurfaceBanner.tsx`'s `Card` shape,
but with no accent spine and no action buttons — informational only):

```tsx
<Card className="w-full p-4" data-testid="train-warmup-banner">
  <div className="flex items-center gap-2">
    <Dumbbell className="size-4 shrink-0" aria-hidden="true" />
    <p className="text-sm font-semibold" data-testid="train-warmup-banner-title">
      Warm-up session
    </p>
  </div>
  <p className="mt-1 text-sm text-muted-foreground" data-testid="train-warmup-banner-body">
    None of your own mistakes are due today — these are practice puzzles.
    {nextDueDate !== null && ` Next review: ${format(parseISO(nextDueDate), 'MMM d, yyyy')}.`}
  </p>
</Card>
```

- **Icon:** `Dumbbell` (lucide-react) — already the app's established icon for "this is
  training-mechanics framing" (`TrainGuestGate.tsx` uses it for the guest-gate screen). Reusing
  it here keeps one icon vocabulary for "this is about the training mechanic, not your games,"
  rather than introducing a second training-adjacent glyph. Rendered `aria-hidden` (the
  adjacent text carries the meaning), `size-4` (16px) to match `TrainReminderResurfaceBanner`'s
  `Bell` sizing exactly.
- **No `accentColor`** on the `Card` (see Color Contract).
- **No buttons inside this banner** — unlike `TrainReminderResurfaceBanner`, this is pure
  framing; the session's own Start/Resume CTA (rendered below, unchanged) is the only action.
- **Placement:** between `TrainHeader` and the `Button` in the shared render branch (the same
  branch `'fresh'`/`'resume'`/`'warmup'` all fall into after the early returns for
  `loading`/`error`/`empty`/`completed`).
- **`data-testid`s:** `train-warmup-banner` (container), `train-warmup-banner-title`,
  `train-warmup-banner-body` — kebab-case, component-prefixed, per CLAUDE.md.

**Removed:** the `'short'` kind's branch (`TrainStartScreen.tsx:129-131` and the
`{state.kind === 'short' && <p>...</p>}` block at `:294-296`), its `LandingState` variant, and
its three tests in `TrainStartScreen.test.tsx` (D-16). `TrainEmptyBody`'s three states are left
untouched (out of scope, F-01).

### 2. `TrainReveal.tsx` — D-19 predicate rewrite (3 sites) + new motif line

**All three existing `puzzle_type !== 'herring'` sites become `source === 'sr_item'`,** reading
a **new** `verdict.source` field on `SolveResponse` (added per research Pitfall 1 — do not read
`revealQuery.data?.source` at these three sites; that introduces a real post-solve flicker
window before the async reveal fetch resolves):

1. `:877` — `showFlawFixedBanner = verdict.source === 'sr_item' && verdict.item_status === 'mastered'`
2. `:915-925` — `guessFeedbackProse(guess, verdict.correct_guess, verdict.source === 'sr_item', verdict.move_quality)`
3. `:1266` — `{verdict.source === 'sr_item' && ( ... game footer JSX ... )}`

No visual change at these three sites for an `SR_ITEM` puzzle — the rewrite is behavior-neutral
for existing traffic. For a `sharp_filler` puzzle, all three now correctly suppress (previously
they would have shown as if for a real game, then broken on a `game_id` the user doesn't own —
research Pitfall 1/2, backend-side).

**New element — motif line.** Placed inside the existing guess-feedback `Card`'s `CardBody`
(the same card holding `guessProse` and the `Also fine: …` row, `:1192-1204`), as a third
optional row:

```tsx
{motif !== null && (
  <p className="text-sm text-muted-foreground" data-testid="train-reveal-motif">
    Motif: {motif}
  </p>
)}
```

where `motif` comes from `revealQuery.data?.motif` (new nullable field on
`PuzzleRevealResponse`, populated only for `source === 'sharp_filler'`). This sits in the same
card as `guessProse`/`showAlsoFine` because it is answer-key-adjacent commentary revealed at the
same moment, on the same async fetch (`revealQuery`) those two already depend on — there is no
timing concern here the way there is for the D-19 predicates, since the motif has no
synchronous-timing requirement (it never gates a suppression, only adds a line once the reveal
query resolves).

- **No badge/chip/pill treatment.** Deliberately plain prose text, not a colored
  `TacticMotifChip`-style badge — that component's color vocabulary (`TAC_*` tokens) belongs to
  the app's own detected-tactic taxonomy (a confidence-gated finding about the user's real
  games), and visually borrowing it for a foreign lichess puzzle's self-declared theme would
  conflate two different kinds of claim. Plain text also keeps this addition inside the
  existing card's established row pattern (`guessProse`, `Also fine: …` are both plain `<p>`
  rows, not chips).
  `TacticMotifChip.tsx` also carries a pre-existing `text-xs` exception (its own comment cites
  "the documented chip exception") — this new line does **not** inherit that exception; it is
  new code and stays on the `text-sm` floor per CLAUDE.md.
- **No icon** on this line (unlike the banner) — it is a single supplementary fact inside an
  already-labeled card, not a new attention-getting element.
- **`data-testid="train-reveal-motif"`.**

**Unchanged (already correct, D-20's other requirements are structural, not visual):**
- No game footer for a sharp filler — already covered by the D-19 rewrite above (③).
- No Analyze deep-link — the Analyze entry point lives in `TrainSolveScreen` gated on
  `game_id !== null`, already null for a sharp filler (D-18) — no new gating needed.
- No tactic stepper — `has_tactic_lines = false` for a sharp filler (backend, D-20) already
  suppresses the SOLV-06 opt-in stepper via its existing gate.
