## The noun that shifted: `hashed_password == ""`

**Before this phase**, an empty `hashed_password` had two meanings fused into one value:
(a) "this account has no password credential", and (b) "this account authenticates by
Google SSO or is a guest" — i.e. an *account type*. `app/services/guest_service.py` writes
`hashed_password=""` at `:40` (guest creation) and `:156` (Google promotion, comment:
"Google users have no password").

**After D-04**, a Google-only user can complete a password reset and end up with both login
methods. The value stops being an account-type marker and becomes purely a *credential
state that has not been set yet*. Any reader that treats an empty hash as "is an SSO user"
becomes wrong the first time a Google user completes a reset.

**Decision: `no-change` (audit-and-confirm, do not promote a new field).**

Rationale: the audit performed at planning time found **zero production readers** of
`hashed_password` as a predicate. `app/` reads it only as a write target in
`guest_service.py`; every account-type branch in the codebase already uses the real
`is_guest` boolean column (`app/models/user.py:30`, and ~20 call sites across routers,
repositories and services). `frontend/src/` has zero occurrences of `hashed_password`,
`has_password`, `is_oauth`, or `is_google`. There is therefore no degraded sentinel to
promote and no new column to add — adding a `has_password` field now would be speculative
schema for zero readers, and this phase's ROADMAP forbids a migration anyway.

**The audit is still a task** (Task 3), because the decision is only sound if the audit is
re-run against the tree the executor actually has, and because an invariant test is what
stops a *future* phase from reintroducing the fused meaning.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|---|---|
| anonymous internet → `POST /api/auth/forgot-password` | Unauthenticated, attacker-chosen email string crosses here. Triggers outbound mail. |
| anonymous internet → `POST /api/auth/reset-password` | Unauthenticated token + new password crosses here. Changes a credential. |
| FlawChess backend → Resend API | `RESEND_API_KEY` crosses outbound over TLS to a fixed constant host. |
| Resend → the user's mailbox | The reset token leaves our control entirely; from here it is protected only by mailbox control and its 1-hour TTL. |
| Reset link → browser URL bar / history / `Referer` | The token sits in a URL, so it is exposed to history, and to any third-party asset the reset page loads. |
