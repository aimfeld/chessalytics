## Background

`query_opening_transitions` picks each transition's sample representative with
`func.min(pg_array([ply, game_id]))` — shallowest ply wins. A custom-FEN game reaches a shared
entry position at a *shallower* ply than standard games (it skips the opening half-moves baked
into its FEN), so `MIN(ply)` **systematically prefers the custom-FEN game** whenever one exists
for that `entry_hash`. `_wrap_transition_row` then replays that representative's SAN prefix from
a fresh `chess.Board()`, `push_san` throws, the row returns `None`, and the **entire** transition
is dropped — all games, not just the odd one.

Observed in prod (Sentry FLAWCHESS-5E, 74 events): an Evans Gambit thematic position with a
50-game transition (W34/D0/L16) dropped because its representative was custom-FEN game `1345513`
(entry reached at ply 7 there vs ~ply 13 in the standard games).

## Tasks

### Task 1 — `extract_initial_fen` helper (D-05, D-06)

In `app/services/normalization.py`, add:

```python
def extract_initial_fen(pgn: str) -> str | None:
    """Return the game's non-standard starting FEN, or None for a standard start."""
```

Rules:
- Requires the `[SetUp "1"]`/`[FEN "..."]` header pair. `[FEN]` without `SetUp "1"` is not a
  custom start by the PGN spec and must return `None`.
- Returns `None` when `canonical_root_fen(fen)` equals `canonical_root_fen(STANDARD_START_FEN)`
  (D-05 — a `[SetUp]` naming the standard position is not a custom start).
- Returns `None` on a malformed/unparseable FEN rather than raising (landmine 5). Validate by
  constructing `chess.Board(fen)`.

Reuse the existing `canonical_root_fen` at `normalization.py:740` — do not add a second
normalization rule.

### Task 2 — Column, schema, and the four normalizer paths (CUSTOM-02)

- `app/models/game.py`: `initial_fen: Mapped[str | None] = mapped_column(Text)` with a comment
  explaining NULL = standard start. No index (D-04 / locked constraint 4).
- `app/schemas/normalization.py`: `initial_fen: str | None = None` on `NormalizedGame`.
- `normalize_chesscom_game` (`:227`) and `normalize_lichess_game` (`:340`): set from
  `extract_initial_fen(pgn)`.
- `normalize_pasted_game` (`:843`): it already derives `root_fen = game.board().fen()` at `:902`

  standard game stays NULL, and pass the result.
- `normalize_flawchess_game` (`:542`): leave NULL explicitly, with a comment (landmine 1).
- `import_service.py`: carry the field onto the `Game` row wherever `NormalizedGame` is unpacked.

### Task 3 — Migration with in-migration backfill (D-04)

New revision on head `e5f71b11fa51`. `op.add_column` (nullable — metadata-only, no rewrite),
then one `UPDATE`:

```sql
UPDATE games
SET initial_fen = substring(pgn from '\[FEN "([^"]*)"\]')
WHERE pgn LIKE '%[SetUp "1"]%'
  AND substring(pgn from '\[FEN "([^"]*)"\]') IS NOT NULL
  AND split_part(substring(pgn from '\[FEN "([^"]*)"\]'), ' ', 1)
      <> 'rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR'
```

The final predicate is the SQL mirror of D-05. Downgrade drops the column.
