# Plan 210-03: Seed `/analysis` Game Mode From the Real Root

## Requirements

| ID | Statement | Success Criterion |
|----|-----------|-------------------|
| CUSTOM-06 | `/analysis` game mode seeds a custom-start library game from its own `initial_fen` | SC-6 |

## Background

Plan 01 makes a custom-start game degrade to a partial board instead of crashing the page.
This plan makes it actually work. `useAnalysisBoard.loadMainLine(sans, newRootFen)`
(`useAnalysisBoard.ts:390`) is **already root-FEN aware** — the only gap is that
`Analysis.tsx:971` hardcodes `STARTING_FEN`:

```ts
loadMainLine(gameData.moves, STARTING_FEN);
```

So the fix is to give the frontend the game's real root and pass it.

## Tasks

### Task 1 — Backend: carry `initial_fen` on the game-detail payload

- `app/schemas/library.py`: add `initial_fen: str | None = None` to the game-analysis detail
  model (the one carrying `moves` at `:154`), with a comment stating that null means the
  standard start and that `moves` is replayed from it.
- `app/services/library_service.py:~734`: populate it alongside `moves=moves_data` from the
  `Game` row.
- Test: a custom-start game's detail response carries its FEN; a standard game's is null.

### Task 2 — Frontend: type and seeding

- `frontend/src/types/library.ts` (near `moves` at `:97`): add `initial_fen: string | null;`
  with the same comment.
- `Analysis.tsx:971`: `loadMainLine(gameData.moves, gameData.initial_fen ?? STARTING_FEN)`.
  Keep the `seededKey` / `gameId` keying exactly as-is (CR-01 same-page game switch).
- Note: `noUncheckedIndexedAccess` is on, but this is a plain optional property, so `??` is the
  correct narrowing, not `!`.

### Task 3 — Tests

- Game mode with a custom-start game: the board's root is the game's FEN and the full mainline
  is loaded (not the empty/partial line plan 01 would produce).
- Standard-start game unaffected.
- Mutation check: revert to hardcoded `STARTING_FEN`, confirm the custom-start test goes red.

### Task 4 — Verify

`uv run pytest -n auto -x`, then `cd frontend && npm run lint && npm test -- --run && npm run build`.
The `npm run build` is required here per `feedback_frontend_run_tsc_build` — this plan changes a
shared type and adds a property access, which lint and tests do not type-check.
