  <behavior>
    - A function whose body nests `if` inside `for` inside `with` reports `max_nesting_depth == 3`.
    - `try` and each `except` handler each count as one level, matching how a reader perceives them.
    - A nested `def` starts a fresh depth-0 scope: the outer function's depth is not inflated by the inner function's body (CLAUDE.md states the limit per function).
    - Comprehensions do not increment depth (v1 rule).
    - `logic_loc` excludes blank lines, comment-only lines, and the function's own docstring lines; it counts the remaining body lines.
    - `raw_loc` is `end_lineno - lineno + 1` and is reported alongside `logic_loc`, never substituted for it.
    - A function carrying `# check-function-size: allow-loc <reason>` on the source line immediately above its `def` is exempt from the LOC threshold only; its depth is still checked, and the JSON record carries `allow_loc: true` with the reason text.
    - Exit code is 1 when any scanned function breaches `--fail-over-depth` or `--fail-over-loc`, 0 otherwise.
    - A directory argument is walked for `*.py`; a file argument is scanned directly.
  </behavior>
  <action>

The test builds small source strings (or `tmp_path` files) and asserts on the analyzer's

- `max_nesting_depth(node: ast.AST) -> int` — increments on `If`, `For`, `AsyncFor`, `While`,
  `With`, `AsyncWith`, `Try` (body and each handler), `Match`; does NOT descend into nested
  `FunctionDef`/`AsyncFunctionDef`/`ClassDef`; does NOT count comprehensions.

- `scan_source(source: str, path: str) -> list[FunctionRecord]`

  (int, default 4), `--fail-over-loc` (int, default 200), `--json`.

`_DEFAULT_MAX_LOGIC_LOC = 200`) rather than bare numbers in the argparse call — CLAUDE.md
