<objective>
Split `eval_apply.py`'s two largest functions along their own already-commented stage
boundaries, without disturbing a single write ordering inside the shared transaction.

Purpose: this is the highest-risk file in the phase. `_classify_and_fill_oracle` (344 raw
lines, cognitive complexity 38) runs six sequential stages against ONE `AsyncSession`, and
three of the project's memory notes bear on it — one of which is stale in a way that could
lead a careless split to reorder a DELETE. `_build_best_move_candidates` breaches both C901
and PLR0912 and carries two Sentry capture sites inside branches. The stages are already
delimited by the author's own numbered comments, so the seams are read, not inferred.

Output: both functions decomposed into named stage helpers with unchanged SQL and ordering,
the file's `per-file-ignores` entry deleted, and 221 existing tests passing untouched.
</objective>

**Planner decision — no sibling module in this phase, and this file is the reason it matters
most.** `tests/test_eval_worker_endpoints.py` patches names directly on the module object
(`monkeypatch.setattr(eval_apply_module, "_classify_and_fill_oracle", ...)`, `"apply_full_eval"`,
`"score_move"`, `"async_session_maker"`). A bare-name call inside a function moved to a sibling
module resolves against the NEW module's globals, so those patches would silently stop
applying and the tests would keep passing while testing nothing. Keep every extraction in
`app/services/eval_apply.py`.

**Three invariants this plan must not break** (RESEARCH verified them against the statements,
not the comments):
1. Stage 3 is a FOUR-way diff/upsert — delete removed plies, insert new plies, update fresh,
   and update-preserving blob columns by omitting the `FLAW_BLOB_COLUMNS` keys from the update
   dict entirely. `existing_plies` and `already_blobbed_plies` are read BEFORE the DELETE; a
   split must pass those already-read values as arguments, never re-derive them afterwards.
2. `_post_move_eval` is the SINGLE site of the +1 post-move storage shift. No extracted helper
   may reimplement `ply + 1` arithmetic; it calls that function.
3. `_resolve_full_eval` deliberately returns `pv_string=None` on a dedup hit. The cached pv is
   carried through a different upstream path at submit time. Do not "fix" this.

**Merge discipline:** this plan shares exactly one file with its five wave-2 siblings —
`pyproject.toml`, where it deletes a single `per-file-ignores` line. Re-read `pyproject.toml`
immediately before that edit. Each wave-2 plan is its own squash-merge unit.
