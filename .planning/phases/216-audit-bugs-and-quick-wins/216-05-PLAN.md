    Finish the handler: wrap the awaited query in `try`/`except Exception as exc`, call
    `sentry_sdk.capture_exception(exc)` in the handler, and return
    `JSONResponse(status_code=status.HTTP_503_SERVICE_UNAVAILABLE, content={"status": "degraded"})`.

    Catch `Exception`, not `BaseException`: `asyncio.CancelledError` derives from
    `BaseException` and must keep propagating, while the timeout raised by
    `asyncio.wait_for` on Python 3.13 is the builtin `TimeoutError`, which is an `Exception`,
    so one clause covers both the timeout and any driver error. Do not write a tuple clause
    listing both a timeout alias and `Exception`; ruff flags the redundancy.

    The 503 body must be exactly `{"status": "degraded"}`. Never interpolate the exception,
    the driver message, the DSN or any connection detail into the response, and never embed
    variable data in an exception message you raise; per CLAUDE.md, structured context goes
    to Sentry via `set_context`/`set_tag`, not into strings (mitigates T-216-03).

    Add two tests to `tests/test_health.py`:
    - Dependency raises: install a per-test override for `get_async_session` that raises, assert 503 and assert the response body equals `{"status": "degraded"}` exactly, then restore the original override object captured from `app.dependency_overrides` before the test, in a `finally`.

Monkeypatch the constant from the test; never change the production value to suit a test. Restore the override in a `finally` the same way.

    Both tests must assert the exact body, not just the status code, so a future change that
    starts leaking error text fails here.
