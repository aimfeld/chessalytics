### 1b. Service-worker-served offline navigation: self.crossOriginIsolated
expected: `true` after loading once online (populates the `html-shell`
  Workbox runtime cache), then going offline in DevTools and reloading —
  per 219-RESEARCH.md Pitfall 2, the `NetworkFirst` route stores whatever
  headers were present on the last successful online fetch, so a shell
  cached AFTER this phase's headers shipped should still read `true` when
  served from cache. A device that goes offline before ever loading this
  build gets a pre-change cached shell without the headers and degrades to
  one thread via `chooseWasmThreadCount()`'s fail-safe — expected, not a bug.
result: **pending** — requires DevTools Offline throttling in a real
  browser tab; not measurable via curl (CacheStorage is browser-internal
  state, not reachable from this session).

  **Orchestrator browser pass (2026-09-06, claude-in-chrome, Chrome/Linux, dev server, `main` at `cb3d7549a`):** **still pending** — DevTools offline throttling is not reachable from the extension; HUMAN-UAT.
