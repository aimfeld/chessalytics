# Quick Task 260805-m73: SEED-139 Eval-Hole Prevention Summary

**Path-C eval holes stop being created instead of resweeping them away by hand: atomic submits that make progress are no longer charged an attempt, the retry budget rose 3 -> 5, the worker retries a timed-out position once before submitting a hole, REMOTE_WORKER.md stops advertising CPU oversubscription, and the holed-game resweep now runs automatically every day.**

## Accomplishments

- `apply_completion_decision` (`app/services/eval_apply.py`) gained a charge-free Path B' branch: a new pure `_count_prior_holes` helper reads the game's pre-write DB hole snapshot from `targets` (never a post-write query, which could never show progress), and any atomic submit that strictly reduces the persistent hole count leaves `full_eval_attempts` untouched and can never reach Path C. Two workers racing on the same lease (a slow worker overruns `LEASE_TTL_SECONDS`, a second worker re-claims and both submit) no longer burn two of the three attempts in one round. `MAX_EVAL_ATTEMPTS` raised 3 -> 5 (nearly free since SEED-076 made re-leases incremental; prod measured zero games needing a 4th attempt after 9,988 hit the 3rd). The drain lane (`preserve_existing_evals=False`) is byte-unchanged — `tests/services/test_full_eval_drain.py`'s 54 pre-existing tests have zero diff.
- `EnginePool.evaluate_nodes_with_pv` / `evaluate_nodes_multipv2` (`app/services/engine.py`) gained an optional keyword-only `timeout_s` override, resolving to `_NODES_TIMEOUT_S` (still 5.0) when omitted so every server-side caller is byte-unchanged.
- `scripts/remote_eval_worker.py` gained a bounded worker-side retry pass: a shared mutable `_RetryBudget` dataclass, an `_is_engine_failure` predicate (mate-aware — a mate-only result is never flagged), and a generic `_retry_timed_out` helper wired into the four passes that can produce a `game_positions` eval hole (`_eval_positions`, `_eval_flaw_blob_positions`, `_eval_atomic_blob_nodes`, `_eval_targeted_second_best`). `_eval_atomic_game` creates ONE budget (`EVAL_RETRY_MAX_POSITIONS=8`) and shares it across all three of its passes — per CYCLE, not per pass. `STALL_THRESHOLD_S` raised 600 -> 720 to absorb the worst-case added retry wall clock (8 x `EVAL_RETRY_TIMEOUT_S=15.0` = 120s) while preserving the same ~100s watchdog margin. `REMOTE_WORKER.md` no longer invites operators past their physical core count and explains why (a timed-out position is discarded, not just slower).
- `app/services/eval_drain.py` gained `run_periodic_holed_game_resweep`, mirroring `run_periodic_guest_cleanup` exactly: sleeps 24h before the first tick, wraps each tick in its own `sentry_sdk.isolation_scope()`, calls `resweep_holed_games(limit=_RESWEEP_TICK_LIMIT, dry_run=False)` — never a dry run — and swallows any exception so a tick failure can't kill the loop. Wired into `app/main.py`'s lifespan as the sixth background loop (started on boot, cancelled+awaited on shutdown); the SEED-138 per-tick-isolation convention comment and `tests/test_background_task_sentry_scope.py`'s `_LOOP_CASES` now cover all six loops.
- `CHANGELOG.md` carries a user-facing `## [Unreleased]` entry. SEED-139 moved to `.planning/seeds/closed/`.
