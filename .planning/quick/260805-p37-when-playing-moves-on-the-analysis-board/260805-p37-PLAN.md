<investigation_findings>
Verified before planning — do not re-derive:

1. **`useTrainFreePlay` wraps `useAnalysisBoard`** (`hooks/useTrainFreePlay.ts:213`,
   `const board = useAnalysisBoard(startFen)`). It re-exports the board's commands as
   `playMove: makeMove`, `playLine: playUciLine`, `goToNode`, `goBack`, `goForward`,
   `goToRoot`, `deleteLine: deleteSubtree`, and `reset` (which calls `loadMainLine`).
   Therefore **one change in `useAnalysisBoard` covers BOTH target surfaces.**
   The scouting hint that `useTrainFreePlay` "already imports from sounds.ts" is WRONG —
   it does not import `lib/sounds` at all. Neither does `useAnalysisBoard`. Both boards
   are fully silent today.

2. **Only two consumers of the hook's state exist:** `pages/Analysis.tsx` and
   `hooks/useTrainFreePlay.ts`. (`hooks/useGameOverlay.ts` imports only the `NodeId`
   *type*, `components/analysis/VariationTree.tsx` and `hooks/uciParser.ts` likewise.)
   No third surface gains sound unexpectedly.

3. **Sound taxonomy already exists and needs no new assets.** `lib/sounds.ts` exports
   `playSound(event)`, `unlockAudio()`, and the `SoundEvent` union; `playSound` no-ops
   when the shared mute preference is set. `TrainLineStepper.replayLine` derives events as
   `chess.inCheck() ? 'check' : move.captured ? 'capture' : 'move'`, and its `goTo`
   plays the arrived-at move's own event when stepping FORWARD, plain `'move'` when
   stepping BACKWARD. There is no castle clip in `SOUND_FILES`; castling is a plain move.

4. **SAN is a faithful, free source for that taxonomy.** Every `MoveNode` stores chess.js
   `move.san`, which carries `+`/`#` for check/mate and `x` for captures (including en
   passant). No re-instantiation of `Chess` is needed to classify a landed node.

5. **Two Analysis.tsx `goToNode` callers must stay silent** (both verified):
   - `pages/Analysis.tsx:952-974` — the navigate-to-`initialPly` effect. It runs in a
     SEPARATE commit from `loadMainLine` (documented at line 950), so silencing
     `loadMainLine` alone does not cover it.
   - `pages/Analysis.tsx:2578-2583` — `handleEvalChartPlyChange`, a **scrub** callback
     fired once per ply while the user drags the eval chart / touch overlay. Unsilenced,
     this machine-guns one sound per ply.
   Every other `goToNode` caller in Analysis.tsx (move-list `onNodeClick`, tags-panel
   cycling, `handlePvChipClick` fork navigation, `handleReset`) is a discrete user click
   and SHOULD sound.

6. **`VariationTree`'s prop type is `onNodeClick: (nodeId: NodeId) => void`** and it
   invokes it with exactly one argument (`VariationTree.tsx:774`, `:921`). Widening
   `goToNode` to `(id, opts?)` stays assignable to that prop and receives
   `opts === undefined` (= sounding) from every click. `onMoveClick` is
   `(uciMoves: string[]) => void` → `playUciLine`, one arg, three call sites.

7. **Mobile is covered automatically.** Analysis renders one shared `boardControls(flat, size)`
   factory for both the desktop panel and the mobile footer (`Analysis.tsx:3022`), and the
   Train reveal has a single controls row. No duplicated markup to keep in sync, and no new
   interactive element is introduced (so no new `data-testid` is required).

8. **jsdom is safe.** `safePlay` reads `audio.play()`'s return without assuming a promise
   and wraps `currentTime` in try/catch, so jsdom's not-implemented `play()` cannot throw.
   Existing Train tests already `vi.mock('@/lib/sounds')`.

  <action>
Add sound emission to `frontend/src/hooks/useAnalysisBoard.ts`. Import `playSound`,
`unlockAudio` and the `SoundEvent` type from `@/lib/sounds`.

**Module-private helpers (not exported — knip runs in CI and fails on dead exports):**

- A SAN-to-`SoundEvent` classifier. Precedence: check marker (`+` or `#`) wins, then
  capture marker (`x`), else the plain move event. Document that this reproduces
  `TrainLineStepper.replayLine`'s `inCheck / captured / plain` precedence without needing a
  `Chess` instance, because chess.js already writes both markers into the stored `san`,
  and that castling has no dedicated clip in `SOUND_FILES` so it is deliberately a plain move.
- A depth function taking `(nodes, id)` and walking `parentId` to the root, returning the
  number of hops. Break out if a `parentId` is not present in the map rather than looping.
  Depth is the tree analogue of `TrainLineStepper`'s stepper index: greater depth means the
  navigation moved forward.

**Refs:**

- `prevNavRef` holding `{ id, depth } | null`, seeded `null` so the first effect run only
  records and stays silent (suppresses the mount).
- `silentNavRef` holding `{ id: NodeId | null } | null`. It NAMES the single landing node id
  whose arrival must not sound, and is consumed (reset to `null`) by the next effect run.
  A ref-held id rather than a boolean is load-bearing: `useTrainFreePlay.start()` calls
  `loadMainLine([], startFen)` and `playUciLine([...prefixUci, moveUci])` in ONE React batch,
  producing ONE commit. A boolean set by `loadMainLine` would swallow the grafted move's
  sound; keying on the id lets `loadMainLine`'s claim (landing `null`) miss the commit's
  actual landing node, so the first free-play move on the Train solution board still sounds.
- `unlockedRef` (boolean) guarding a one-shot `unlockAudio()`.

**`loadMainLine`:** before its `setState`, set `silentNavRef.current` to the id it will land
on (`lastId` when the replay produced nodes, otherwise `null`). Seeding a tree from the URL
or resetting free play is not a user move.

**`goToNode`:** widen the signature to `(id: NodeId, opts?: { silent?: boolean }) => void`
and set `silentNavRef.current` to `{ id }` when `opts?.silent` is true. Keep the existing
already-on-this-node bail. Update `AnalysisBoardReturn.goToNode`'s type to match and document
that the optional second parameter exists for programmatic seeding and continuous scrubbing,
and that omitting it (every UI click path) sounds. Assignability to
`VariationTree`'s `onNodeClick: (nodeId: NodeId) => void` is preserved.

**One-shot iOS unlock:** at the top of `makeMove`, `goBack`, `goForward`, `goToRoot`,
`playUciLine`, and the non-silent branch of `goToNode`, call `unlockAudio()` once behind
`unlockedRef`. Comment why: WebKit grants a media element playback permission only when
`play()` is first called inside a user gesture, and the sound below is emitted from a
passive effect one tick later. Every one of these call sites is reached from a real gesture
(board drop, control button, arrow key, move-list click, engine-line chip); the programmatic
paths — `loadMainLine`, `insertPvLine`, and silent `goToNode` — deliberately do NOT unlock,
so the one-shot guard is never burned on a non-gesture that WebKit would reject anyway.
This mirrors what `Bots.tsx` and `useBotGame` already do.

**Emission effect** (place it after the existing `stateRef` sync effect, before the
keyboard-handler effect), depending on `state.currentNodeId` and `state.nodes`:

1. Compute the landing node (`state.nodes.get(state.currentNodeId)` when non-null) and its depth.
2. Read `prevNavRef.current` into a local, then overwrite `prevNavRef.current` with the new
   `{ id, depth }` — unconditionally, so a suppressed or no-op run still keeps the baseline honest.
3. If `silentNavRef.current` is non-null: clear it and return when its `id` equals the landing
   id; otherwise clear it and continue (a different node landed, so the claim is stale).
4. Return when the previous record is `null` (mount).
5. Return when the previous id equals the landing id (the tree changed but the shown position
   did not — e.g. `insertPvLine` parking at the fork the board already sits on, or a
   `deleteSubtree` of a line the board is not inside).
6. Call `playSound` with the landing node's SAN-derived event when the new depth is greater
   than the previous depth AND a landing node exists; otherwise with the plain move event.

Do NOT emit from inside any `setState` updater — React StrictMode double-invokes updaters in
dev and would double-play. Do NOT add a `useEffect` dependency on the returned callbacks.

**Tests** — extend `frontend/src/hooks/__tests__/useAnalysisBoard.test.ts`. Add
