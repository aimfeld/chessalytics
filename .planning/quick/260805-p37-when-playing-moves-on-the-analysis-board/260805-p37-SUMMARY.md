**Centralized move-sound emission (check/capture/plain move, matching TrainLineStepper's precedence) added to `useAnalysisBoard` via a depth-comparison + SAN-classification effect — covers both the /analysis board and the Train puzzle-solution free-play board for free, with two explicit silence opt-outs (URL seeding, eval-chart scrub) in Analysis.tsx.**

## Accomplishments
- `useAnalysisBoard.ts` now emits `move`/`capture`/`check` sounds from a single commit-triggered
  effect, classifying the landed node's stored SAN and comparing tree depth against the previous
  landing to distinguish forward (own event) from backward (`move`) navigation.
- `useTrainFreePlay` wraps `useAnalysisBoard`, so the Train puzzle-solution board's free-play
  moves — including the very first free move, grafted in the same React batch as a
  tree-resetting `loadMainLine` — now sound too, with zero changes to `useTrainFreePlay.ts`.
- `goToNode` widened to accept `{ silent: true }`; exactly two Analysis.tsx call sites
  (URL-seeding `initialPly` navigation, eval-chart scrub) pass it. Every other `goToNode`/
  `makeMove`/`goBack`/`goForward`/`goToRoot`/`playUciLine` call site sounds unchanged.
- One-shot `unlockAudio()` gate added to every gesture-driven command for iOS/WebKit playback
  unlock, mirroring the existing `Bots.tsx`/`useBotGame` pattern.
- 14 new hook-level tests covering every `<behavior>` bullet in the plan; extended two test
  suites' existing `@/lib/sounds` mocks (`TrainSolveScreen.test.tsx` was missing `unlockAudio`;
  `Analysis.test.tsx` had no sounds mock at all, producing real jsdom Audio-noise).

## Decisions Made
- Depth-based forward/backward detection (walking `parentId` to root) rather than tracking a
  stepper index, since the analysis board is a branching tree, not a flat line.
- `silentNavRef` keyed on the landing node id (not a boolean): `useTrainFreePlay.start()` calls
  `loadMainLine([], startFen)` then `playUciLine([...])` in one React batch, and a boolean claim
  from `loadMainLine` would incorrectly suppress the grafted move's sound too. Keying on id makes
  that stale claim (landing `null`) miss the batch's actual landing node.
- `unlockAudio()` deliberately NOT called from `insertPvLine` (a programmatic PV-line graft, not
  a user gesture) — matches the plan's explicit exclusion list.
