<objective>
Fix the chess.com 404 monthly-archive skip (Sentry FLAWCHESS-39): make the skip event
triageable, and stop both import cursors from advancing past a month that was skipped.

**Decision map** — the five locked decisions are cited as D-01..D-05 throughout:
- **D-01** Do NOT make 404 hard-fail like 5xx. Skip-but-remember is the required shape.
- **D-02** Fix A — attach Sentry context (`archive_url` + `status` minimum), message string unchanged.
- **D-03** Fix B — do not advance the cursor past a skipped month, on BOTH paths, without
  breaking Pitfall 1 (200-empty months must still advance) and without stalling the walk.
- **D-04** Scope discipline: Fix A + Fix B only. No retry-loop refactor, no new table, no
  change to 5xx/429 behavior, no lichess changes.
- **D-05** Tests: update the existing 410 test; prove the cursor does NOT advance past a skip
  on both paths and that a 200-empty month DOES; every assertion must fail on revert.

Purpose: today a 404 on `/pub/player/{user}/games/YYYY/MM` is treated as "attempted-but-empty",
so the month is dropped and both cursors move past it — permanent silent data loss. This was
empirically disproven against the live API: a genuinely empty month and a pre-join month both
return **HTTP 200** with `{"games":[]}`; only a chess.com server-side fault returns 404 (probed
2026-08-06 for `ocnafr`: 2025/09 → 200 empty, 2020/01 → 200 empty, 2025/11 → persistent 404
across 3/3 attempts with the ambiguous "An internal error has occurred" body, while 2025/11 IS
listed in that player's `/games/archives` index). This is the same failure class the team already
fixed for 5xx (`.planning/debug/prod-import-missed-games.md`); 404 slips through the identical hole.

Output: one new Sentry context at the skip site, a skip-reporting callback on the forward
generator consumed by `_complete_import_job`, a cursor freeze on the backward walk, tests that
fail on revert, and a CHANGELOG bullet.
</objective>
