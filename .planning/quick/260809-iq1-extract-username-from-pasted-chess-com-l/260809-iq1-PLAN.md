<objective>
Extract the bare username when a user pastes (or types) a chess.com / lichess profile URL into a
username field, on both the Import page and the API.

Purpose: users routinely copy their profile URL rather than their handle; today that string is sent
verbatim to the platform API and the import fails with an unhelpful "user not found".
Output: a shared frontend TS util + matching backend Pydantic validators, both covered by unit tests.

Locked decisions from /gsd-explore (do not revisit):
- D-01: shared frontend TS util recognizing `chess.com/member/<name>` and `lichess.org/@/<name>`,
  with or without protocol / `www`, tolerating trailing slash and query string; non-URL input passes
  through unchanged (trimmed).
- D-02: applied on paste/blur to BOTH username fields in `frontend/src/pages/Import.tsx`, visibly
  replacing the field content. No error state, no toast.
- D-03: matching Pydantic validator on `ImportRequest.username` (`app/schemas/imports.py`) and on
  `UserProfileUpdate.chess_com_username` / `.lichess_username` (`app/schemas/users.py`), platform-aware
  where the schema knows the platform.
- D-04: frontend util unit tests + backend validator tests.
</objective>

<interface_context>
Frontend util (new, `frontend/src/lib/platformUsername.ts`):

```
export type UsernamePlatform = 'chess.com' | 'lichess';
export function extractPlatformUsername(input: string, platform: UsernamePlatform): string;
```

Backend helper (new, `app/core/platform_usernames.py`):

```
UsernamePlatform = Literal["chess.com", "lichess"]
def extract_platform_username(value: str, platform: UsernamePlatform | None = None) -> str
```

`platform=None` means "accept either platform's URL form" — the D-03 fallback for the case where the
schema cannot determine the platform (only reachable on `ImportRequest` when `platform` itself failed
validation).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Import page field | user-controlled paste/typed text, including arbitrary URLs |
| client -> FastAPI (`POST /imports`, `PUT /users/me/profile`) | untrusted `username` string crossing into schema validation, then into an outbound platform API call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-IQ1-01 | Denial of Service | `extract_platform_username` / `extractPlatformUsername` regexes | medium | mitigate | Regexes are anchored with a single flat `[A-Za-z0-9_-]+` capture and no nested quantifiers or overlapping alternation, so matching is linear in input length (no catastrophic backtracking on an attacker-chosen paste). |
| T-IQ1-02 | Tampering | `ImportRequest.username` `max_length=100` | medium | mitigate | The `before` validator shortens a URL to its username BEFORE the length constraint, so it relaxes rather than bypasses the bound — the post-validator value is still length-checked, and the raw body is already bounded by the ASGI request-size limit. |
| T-IQ1-03 | Tampering | outbound chess.com / lichess URL construction from `username` | medium | mitigate | The extracted username is constrained to `[A-Za-z0-9_-]+`, so a recognized paste can never inject `/`, `?`, `@`, or `..` into a downstream platform API path. Unrecognized input is passed through unchanged and remains subject to the existing `max_length=100` plus the platform API's own 404. |
| T-IQ1-04 | Information Disclosure | pasted URL containing a session/query token | low | accept | Extraction discards the query string, which strictly reduces what is stored versus today's verbatim value. No new logging of the raw pasted string is added. |

No package-manager installs in this change — no `[ASSUMED]`/`[SUS]` package legitimacy checkpoint is required.
</threat_model>
