<objective>
Make `drill_items.fail_count` a non-resetting LIFETIME lapse counter and park an item
at 6 lifetime lapses (SEED-154), so a puzzle the user alternately solves and fails can
finally leave the Train SR pool.

Purpose: today such an item never exits. `MASTERED` needs 3 *consecutive* correct
solves (alternation oscillates between streak 0 and 1 forever) and `PARKED` needs
`fail_count >= 3` **and** `ever_correct is False` — but the first correct answer sets
`ever_correct=True` and zeroes `fail_count`, after which the counter can never increment
again. The item occupies an SR slot roughly every 1.5 days, forever.

Output: two park doors in the one pure function that owns SR transitions.
- **Door A** (unchanged): `not ever_correct and fail_count >= PARK_FAIL_THRESHOLD` (3).
- **Door B** (new): `fail_count >= LEECH_FAIL_THRESHOLD` (6), regardless of `ever_correct`.

**Locked decision (Adrian, 2026-08-26): park-only. No un-park affordance.** No new
endpoint, no new repository method, no parked-item listing UI, no un-park button. The
underlying flaw stays visible in the Games/flaws surfaces regardless, and an un-park
lever can be added later on evidence once the parked count is actually non-zero for real
users. This matches the standing Phase 191 D-17 ("Parked is a count only… no un-park").
Do not re-open.

**No migration, and no risk of mass-parking on deploy.** `drill_items.fail_count`
already exists. Every live row is provably below the new threshold: rows are created
with `fail_count=0`, and the ONLY writer is `apply_result` (via `record_solve_result`),
which under today's semantics zeroes the counter on every correct answer and caps
never-solved items at 3 (where they park). So today every `ever_correct=True` row holds
`fail_count == 0` and every unparked `ever_correct=False` row holds `fail_count <= 2` —
all six lapses below Door B start accruing from the next wrong answer. No backfill.

**Why no tracer task:** the tracer-first default buys nothing here. There is no new
wiring to prove — the repository already reads `fail_count`/`ever_correct` into
`ItemState` and writes the result back verbatim, and the router already surfaces the
resulting status. The entire behavior change lives inside one pure stdlib-only function
with existing pure unit tests, so Task 1's unit suite IS the end-to-end proof and Task 3
confirms the untouched layers still agree.
</objective>
